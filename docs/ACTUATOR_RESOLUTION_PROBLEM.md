# Суть проблемы с резолвом актуаторов

## Краткое описание

При резолве привязок каналов актуаторов (`bind`) к связанным устройствам возникают проблемы с получением и обработкой данных о привязках, что приводит к отображению каналов как "(не привязан)" даже когда привязки существуют.

## Основные проблемы

### 1. Каналы не запрашиваются при начальной загрузке

**Проблема:** При старте `monitor.js` выполняется массовый GET для всех устройств, но каналы актуаторов не включаются в этот запрос.

**Последствия:**
- Состояния каналов (включая `bind`) не загружаются сразу
- Резолв привязок невозможен до получения данных каналов
- UI показывает каналы как "(не привязан)" даже при наличии привязок

**Код:** В `ws.on('open')` каналы актуаторов должны добавляться в массив `deviceIds` для массового GET, но это не происходит автоматически.

### 2. Частичные обновления каналов без поля `bind`

**Проблема:** Каналы часто приходят через WebSocket с частичными payload, в которых отсутствует поле `bind`.

**Последствия:**
- Даже если канал был загружен, обновления могут не содержать `bind`
- Требуются дополнительные запросы для получения полного состояния
- Увеличивается нагрузка на WebSocket и задержка отображения

**Код:** В строках 3318-3333 `monitor.js` есть логика дозапроса, но она работает только для выбранного актуатора.

### 3. Ограничительное условие дозапроса `bind`

**Проблема:** Дозапрос состояния канала (для получения `bind`) выполняется только если:
- Канал принадлежит выбранному актуатору (`selectedId === actuatorId`)
- Поле `bind` отсутствует в payload

**Последствия:**
- Каналы невыбранных актуаторов не дозапрашиваются
- При переключении между актуаторами требуется время на загрузку данных
- Пользователь видит неполную информацию о привязках

**Код:** Строка 3330 в `monitor.js`:
```javascript
if (selectedId && selectedId === actuatorId) {
  display.requestChannelState(deviceId);
}
```

### 4. Асинхронность загрузки связанных устройств

**Проблема:** Устройства, упомянутые в `bind` каналов, могут быть еще не загружены в момент резолва.

**Последствия:**
- `linkedDevice` остается `null` даже при наличии `bind`
- Требуются дополнительные запросы для загрузки связанных устройств
- Резолв происходит с задержкой или не происходит вообще

**Код:** В строках 1881-1883, 1927-1929, 1956-1958 `monitor.js` есть логика запроса отсутствующих устройств, но она срабатывает только при наличии `bind` в `channelState`.

### 5. Неэффективный поиск связанных устройств

**Проблема:** Поиск устройства по `bind` выполняется только по точному совпадению `id`, без учета возможных вариантов формата.

**Последствия:**
- Устройства могут не находиться, если формат `bind` отличается от формата `id`
- Fallback поиск по `code` и `name` выполняется, но может не покрывать все случаи

**Код:** Строки 1871-1878, 1917-1924, 1946-1953 в `monitor.js`:
```javascript
linkedDevice = this.allDevices.find(d => d.id === channelState.bind);
if (!linkedDevice && typeof channelState.bind === 'string') {
  linkedDevice = this.allDevices.find(d => 
    d.code === channelState.bind || 
    d.name === channelState.bind ||
    d.id === channelState.bind
  );
}
```

## Цепочка проблем

1. **Старт приложения** → Каналы не загружаются в массовом GET
2. **Частичные обновления** → Каналы приходят без `bind`
3. **Ограничение дозапроса** → Дозапрос работает только для выбранного актуатора
4. **Отсутствие связанных устройств** → Устройства из `bind` не загружены
5. **Результат** → UI показывает "(не привязан)" вместо реальных привязок

## Требуемые исправления

1. **Добавить каналы актуаторов в массовый GET при загрузке**
   - В `ws.on('open')` после получения списка устройств добавить каналы всех актуаторов в `deviceIds`

2. **Расширить логику дозапроса каналов**
   - Убрать ограничение на выбранный актуатор или сделать его опциональным
   - Добавить приоритетный дозапрос для каналов с отсутствующим `bind`

3. **Улучшить загрузку связанных устройств**
   - При обнаружении `bind` в канале сразу запрашивать связанное устройство
   - Кэшировать запросы, чтобы не дублировать их

4. **Оптимизировать поиск устройств**
   - Расширить fallback логику поиска
   - Добавить нормализацию форматов ID для сравнения

5. **Добавить механизм повторного резолва**
   - При получении новых данных пересчитывать `linkedDevice` для всех каналов
   - Обновлять UI при изменении состояния резолва
