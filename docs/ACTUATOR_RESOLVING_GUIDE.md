# Руководство по резолвингу актуаторов

## Быстрый старт

### Использование monitor.js (основной способ)

```bash
node src/monitor.js
```

**Что улучшено:**
- ✅ Показываются все поля связанных устройств (title, code, name)
- ✅ Выводится bind UUID для отладки
- ✅ Исправлена логика отображения DO каналов (ВКЛ/ВЫКЛ)
- ✅ Все каналы актуаторов запрашиваются автоматически

### CLI утилиты

#### 1. Список всех актуаторов

```bash
node scripts/list-actuators-via-websocket.js
```

**Результат:** Список всех актуаторов с командами для резолвинга

#### 2. Резолвинг конкретного актуатора (рекомендуемый способ)

```bash
node scripts/resolve-actuator-channels.js "<ID_АКТУАТОРА>" [ТИП_УСТРОЙСТВА]
```

**Особенности:**
- ✅ Поддерживает локальные и удалённые подключения через gateway
- ✅ Автоматически определяет тип устройства (или можно указать явно)
- ✅ Запрашивает все каналы и связанные устройства автоматически
- ✅ Выводит понятный форматированный результат

**Примеры:**

```bash
# Локальное подключение
node scripts/resolve-actuator-channels.js "ec:c6:04:79:77:34"

# Локальное подключение с указанием типа устройства (ускоряет работу)
node scripts/resolve-actuator-channels.js "ec:c6:04:79:77:34" 0xb5

# Подключение через gateway "Почтовая"
REACTHOME_WS_URI="wss://gate.reacthome.net/fd6765f1-ed61-4ae4-8d72-9a078a9f4316" \
node scripts/resolve-actuator-channels.js "ec:c6:04:79:77:34" 0xb5

# Подключение через gateway "Миндальный"
REACTHOME_WS_URI="wss://gate.reacthome.net/d31775ae-19e8-40c9-81df-d6d672379563" \
node scripts/resolve-actuator-channels.js "ec:c6:04:79:77:34" 0xb5
```

**Типы устройств (hex):**
- `0xb5` - MIX_6x12_RS (6 DO + 12 DIM каналов)
- `0xa1` - RELAY_12 (12 DO каналов)
- `0xa4` - DIM_8 (8 DIM каналов)
- `0xaa` - MIX_2 (2 DO + 2 DIM канала)

#### 3. Альтернативный скрипт резолва

```bash
node scripts/resolve-actuator-via-websocket.js "<ID_АКТУАТОРА>"
```

**Примеры:**
```bash
# DIM_8
node scripts/resolve-actuator-via-websocket.js "68:27:19:e4:49:17"

# RELAY_12
node scripts/resolve-actuator-via-websocket.js "54:10:ec:19:ce:8b"

# MIX_1
node scripts/resolve-actuator-via-websocket.js "68:27:19:e4:48:38"
```

## Поддерживаемые типы актуаторов

| Категория | Типы | Каналы | Hex код |
|-----------|------|--------|---------|
| **Реле** | RELAY_12, RELAY_6, RELAY_2 | DO (0/1) | 0xa1, 0xa0, 0x23 |
| **Диммеры** | DIM_8, DIM_4, DIM_12, LANAMP | DIM (0-255) | 0xa4, 0xa3, 0xad, 0xa5 |
| **Аналоговые** | AO_4_DIN | AO (0-255) | 0xa9 |
| **Смешанные** | MIX_1, MIX_2, MIX_H, MIX_6x12_RS | DO + DIM | 0xab, 0xaa, 0x41, 0xb5 |

**Примеры использования:**
- `MIX_6x12_RS` (0xb5): 6 DO каналов + 12 DIM каналов
- `RELAY_12` (0xa1): 12 DO каналов
- `DIM_8` (0xa4): 8 DIM каналов

## Технические детали

### Работа через Gateway

Скрипт `resolve-actuator-channels.js` поддерживает подключение через удалённый gateway (`wss://gate.reacthome.net`).

**Особенности работы через gateway:**
1. Автоматически определяет gateway по URL и использует subprotocol `listen`
2. Обрабатывает session ID префиксы в сообщениях (36 символов UUID)
3. Отправляет чистый JSON без префиксов (gateway сам добавляет session ID)
4. Имеет увеличенные таймауты для работы через сеть

**Формат подключения:**
```bash
REACTHOME_WS_URI="wss://gate.reacthome.net/<DAEMON_UUID>" \
node scripts/resolve-actuator-channels.js "<ACTUATOR_ID>" [DEVICE_TYPE]
```

**Алгоритм работы скрипта:**
1. Подключается к WebSocket (локально или через gateway)
2. Запрашивает данные актуатора для определения типа (или использует указанный тип)
3. По типу устройства определяет количество и типы каналов
4. Генерирует ID всех каналов (формат: `{MAC}/do/{N}`, `{MAC}/dim/{N}`, `{MAC}/ao/{N}`)
5. Запрашивает состояние всех каналов одним GET запросом
6. Собирает UUID связанных устройств из поля `bind` каждого канала
7. Запрашивает данные связанных устройств для резолва их названий
8. Форматирует и выводит результаты с привязками

### Автоматический запрос каналов в monitor.js

При подключении к WebSocket `src/monitor.js` автоматически:
1. Определяет все актуаторы в системе
2. Генерирует ID всех каналов (do/1, dim/1, ao/1, и т.д.)
3. Запрашивает состояние всех каналов
4. Запрашивает связанные устройства по bind UUID

### Периодическое обновление

Состояние каналов обновляется каждые 3 секунды вместе с основными устройствами.

### Кэширование

Информация о каналах кэшируется в памяти для быстрого доступа.

## Решение проблем

### Проблема: Каналы не отображаются

**Решение:** Подождите несколько секунд после запуска monitor.js - каналы запрашиваются после загрузки основных устройств.

### Проблема: Устройство не найдено

**Причины:**
1. UUID в bind указывает на несуществующее устройство
2. Устройство было удалено, но bind остался
3. Устройство еще не загружено (подождите)

**Отладка:**
- Проверьте bind UUID в выводе
- Используйте CLI утилиту для резолвинга
- Проверьте БД на наличие устройства

### Проблема: Помещение не отображается

**Причина:** UUID помещения не запрошен или отсутствует в системе

**Решение:** Проверьте поле `site` в данных устройства

### Проблема: Таймаут при работе через gateway

**Причины:**
1. Gateway недоступен или демон не подключён к gateway
2. Медленное соединение с удалённым сервером
3. Большое количество каналов и устройств

**Решение:**
- Проверьте доступность gateway
- Укажите тип устройства явно для ускорения работы: `node scripts/resolve-actuator-channels.js "ID" 0xb5`
- Убедитесь, что демон подключён к gateway

### Проблема: Все каналы показывают "(не привязан)"

**Причины:**
1. Каналы действительно не привязаны к устройствам
2. Поле `bind` отсутствует в данных каналов
3. Связанные устройства не найдены по UUID

**Решение:**
- Проверьте данные каналов в базе данных
- Убедитесь, что связанные устройства существуют
- Используйте отладку: установите `DEBUG=1` для вывода дополнительной информации

## Формат вывода скрипта resolve-actuator-channels.js

### Пример успешного резолва

```
═══════════════════════════════════════════════════════════

📊 РЕЗУЛЬТАТЫ РЕЗОЛВА:

Найдено каналов: 18 из 18 запрошенных

Диммер (DIM) каналы:
  DIM/1: — (0-255) → (не привязан)
  DIM/2: — (0-255) → (не привязан)
  ...

Реле (DO) каналы:
  DO/1: ВКЛ → Вход воды (valve_water)
  DO/2: ВКЛ → Горячая вода (valve_water)
  DO/3: ВКЛ → Обратка воды (valve_water)
  DO/4: ВЫКЛ → Калитка (valve_water)
  DO/5: ВЫКЛ → (не привязан)
  DO/6: ВЫКЛ → (не привязан)

═══════════════════════════════════════════════════════════
```

**Легенда:**
- `ВКЛ/ВЫКЛ` - состояние реле (DO) канала
- `0-255` - значение диммера (DIM) канала
- `—` - значение отсутствует
- `→` - привязка к устройству
- `⚠️ Устройство не найдено` - UUID в bind не найден в системе
