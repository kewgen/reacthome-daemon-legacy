# Руководство по резолвингу актуаторов

## Быстрый старт

### Использование monitor.js (основной способ)

```bash
node src/monitor.js
```

**Что улучшено:**
- ✅ Показываются все поля связанных устройств (title, code, name)
- ✅ Выводится bind UUID для отладки
- ✅ Исправлена логика отображения DO каналов (ВКЛ/ВЫКЛ)
- ✅ Все каналы актуаторов запрашиваются автоматически

### CLI утилиты

#### 1. Список всех актуаторов

```bash
node scripts/list-actuators-via-websocket.js
```

**Результат:** Список всех актуаторов с командами для резолвинга

#### 2. Резолвинг конкретного актуатора

```bash
node scripts/resolve-actuator-via-websocket.js "<ID_АКТУАТОРА>"
```

**Примеры:**
```bash
# DIM_8
node scripts/resolve-actuator-via-websocket.js "68:27:19:e4:49:17"

# RELAY_12
node scripts/resolve-actuator-via-websocket.js "54:10:ec:19:ce:8b"

# MIX_1
node scripts/resolve-actuator-via-websocket.js "68:27:19:e4:48:38"
```

## Формат вывода в monitor.js

### Пример для актуатора с привязками

```
Каналы актуатора:
  Диммер (DIM) каналы:
    DIM/2: 0 (0-255) → Освещение (light_220)
      bind: e3549d47-f090-448a-8997-3483797b4196
      └─ title: "Освещение", code: "4.D.L.2"
```

### Пример для канала без привязки

```
    DIM/7: 255 (0-255) → (не привязан)
```

### Пример для канала с отсутствующим устройством

```
    DIM/1: 0 (0-255) → ⚠️  Устройство не найдено
      bind: fd8e5a40-79f4-4990-87b5-64f79b2e7029 [запрошено через WebSocket]
```

## Поддерживаемые типы актуаторов

| Категория | Типы | Каналы |
|-----------|------|--------|
| **Реле** | RELAY_12, RELAY_6, RELAY_2 | DO (0/1) |
| **Диммеры** | DIM_8, DIM_4, LANAMP | DIM (0-255) |
| **Аналоговые** | AO_4_DIN | AO (0-255) |
| **Смешанные** | MIX_1, MIX_H | DO + DIM |

## Технические детали

### Автоматический запрос каналов

При подключении к WebSocket `src/monitor.js` автоматически:
1. Определяет все актуаторы в системе
2. Генерирует ID всех каналов (do/1, dim/1, ao/1, и т.д.)
3. Запрашивает состояние всех каналов
4. Запрашивает связанные устройства по bind UUID

### Периодическое обновление

Состояние каналов обновляется каждые 3 секунды вместе с основными устройствами.

### Кэширование

Информация о каналах кэшируется в памяти для быстрого доступа.

## Решение проблем

### Проблема: Каналы не отображаются

**Решение:** Подождите несколько секунд после запуска monitor.js - каналы запрашиваются после загрузки основных устройств.

### Проблема: Устройство не найдено

**Причины:**
1. UUID в bind указывает на несуществующее устройство
2. Устройство было удалено, но bind остался
3. Устройство еще не загружено (подождите)

**Отладка:**
- Проверьте bind UUID в выводе
- Используйте CLI утилиту для резолвинга
- Проверьте БД на наличие устройства

### Проблема: Помещение не отображается

**Причина:** UUID помещения не запрошен или отсутствует в системе

**Решение:** Проверьте поле `site` в данных устройства
