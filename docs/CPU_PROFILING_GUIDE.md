# Руководство по профилированию CPU для Node.js процессов на малинке

## Зачем
Профилирование CPU помогает выявить узкие места в производительности, найти функции, которые потребляют больше всего процессорного времени, и оптимизировать код.

## Методы профилирования

### Метод 1: Программное профилирование (без перезапуска процесса)

Самый простой способ - использовать скрипт, который собирает статистику CPU без перезапуска процесса.

```bash
./scripts/system/profile-cpu-on-pi.sh [process_name] [duration_seconds]
```

**Примеры:**
```bash
# Профилирование процесса daemon на 30 секунд
./scripts/system/profile-cpu-on-pi.sh daemon 30

# Профилирование процесса events на 60 секунд
./scripts/system/profile-cpu-on-pi.sh events 60
```

**Что делает:**
- Подключается к малинке по SSH
- Находит процесс в PM2
- Запускает скрипт профилирования на указанное время
- Собирает статистику памяти и CPU
- Сохраняет результаты в `./reports/cpu-profiles/`

**Результаты:**
- `cpu-profile-{process}-{timestamp}.cpuprofile` - профиль в формате Chrome DevTools
- `cpu-profile-{process}-{timestamp}-metadata.json` - метаданные профилирования

### Метод 2: Детальное профилирование через --cpu-prof флаг

Для более детального анализа нужно перезапустить процесс с флагом `--cpu-prof`.

#### Шаг 1: Перезапуск процесса с профилированием

```bash
./scripts/system/restart-with-cpu-prof-on-pi.sh [process_name] [prof_dir]
```

**Пример:**
```bash
# Перезапуск daemon с профилированием, профили в /tmp/cpu-profiles
./scripts/system/restart-with-cpu-prof-on-pi.sh daemon /tmp/cpu-profiles
```

**Что происходит:**
- Процесс перезапускается с флагом `--cpu-prof --cpu-prof-dir=/tmp/cpu-profiles`
- Node.js автоматически создаёт `.cpuprofile` файлы при завершении процесса
- Можно создать профиль вручную: `kill -USR2 $(pm2 pid process_name)`

#### Шаг 2: Скачивание профилей

```bash
./scripts/system/download-cpu-profiles-from-pi.sh [process_name] [prof_dir]
```

**Пример:**
```bash
./scripts/system/download-cpu-profiles-from-pi.sh daemon /tmp/cpu-profiles
```

#### Шаг 3: Анализ профилей в Chrome DevTools

1. Откройте Chrome и перейдите: `chrome://inspect`
2. Нажмите "Open dedicated DevTools for Node"
3. Перейдите во вкладку **Performance**
4. Нажмите **Load profile** и выберите `.cpuprofile` файл
5. Анализируйте:
   - **Call Tree** - дерево вызовов функций
   - **Bottom Up** - функции, отсортированные по времени выполнения
   - **Flame Chart** - визуализация времени выполнения

### Метод 3: Профилирование через Chrome DevTools Protocol (--inspect)

Для интерактивного профилирования можно использовать Inspector.

```bash
./scripts/system/profile-cpu-with-inspector-on-pi.sh [process_name] [duration] [port]
```

**Требования:**
- Процесс должен быть перезапущен с флагом `--inspect=0.0.0.0:9229`
- Нужен SSH туннель для доступа к Inspector порту

## Рекомендации

### Когда использовать каждый метод:

1. **Метод 1 (программное)** - для быстрой проверки, когда не нужно перезапускать процесс
2. **Метод 2 (--cpu-prof)** - для детального анализа производительности, когда можно перезапустить процесс
3. **Метод 3 (Inspector)** - для интерактивной отладки в реальном времени

### Оптимальная длительность профилирования:

- **Короткие операции** (< 1 секунды): 10-30 секунд
- **Средние операции** (1-10 секунд): 30-60 секунд
- **Долгие операции** (> 10 секунд): 60-300 секунд

### Что искать в профилях:

1. **Горячие функции** - функции, которые занимают больше всего CPU времени
2. **Частые вызовы** - функции, которые вызываются очень часто
3. **Долгие операции** - синхронные операции, блокирующие event loop
4. **Утечки CPU** - функции, которые постоянно выполняются

## Примеры анализа

### Найти самую медленную функцию:

1. Откройте профиль в Chrome DevTools
2. Перейдите в **Bottom Up**
3. Отсортируйте по **Self Time**
4. Первая функция - самая медленная

### Найти функцию с наибольшим количеством вызовов:

1. Откройте профиль в Chrome DevTools
2. Перейдите в **Bottom Up**
3. Отсортируйте по **Total Time**
4. Проверьте количество вызовов в колонке **Call Count**

### Проверить блокирующие операции:

1. Откройте профиль в Chrome DevTools
2. Посмотрите на **Flame Chart**
3. Ищите длинные блоки (желтые/красные полосы)
4. Это указывает на синхронные операции, блокирующие event loop

## Устранение проблем

### Процесс не найден

```bash
# Проверьте список процессов
ssh pi@192.168.88.4 "cd /home/pi/reacthome-daemon && pm2 list"
```

### Профили не создаются

1. Убедитесь, что процесс запущен с флагом `--cpu-prof`
2. Проверьте права доступа к директории профилей
3. Проверьте, что процесс не завершился до создания профиля

### Не удаётся скачать профили

1. Проверьте SSH подключение
2. Убедитесь, что файлы существуют на малинке
3. Проверьте права доступа к файлам
