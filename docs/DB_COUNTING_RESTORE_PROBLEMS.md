# Проблемы с подсчётом записей в БД и восстановлением БД

## 🔴 Критические проблемы

### 1. Неправильный путь к БД в скриптах
- **Проблема**: `count-db-pi.sh` использует `/home/pi/var/db` вместо `/home/pi/reacthome-daemon/var/db`
- **Последствие**: Скрипт может считать записи из неправильной БД или не найти БД
- **Статус**: ❌ Требует исправления

### 2. Отсутствие проверки доступности БД
- **Проблема**: Нет проверки, что БД существует и доступна перед подсчётом
- **Последствие**: Ошибки при подсчёте, если БД заблокирована или не существует
- **Статус**: ❌ Требует исправления

### 3. Потеря записей после восстановления
- **Проблема**: После восстановления БД количество записей уменьшается (1987 → 108)
- **Возможные причины**:
  - Изменение MAC-адреса демона (записи привязаны к MAC)
  - Демон очищает "осиротевшие" записи при старте
  - Проблемы с иерархией данных (project → site → device)
- **Статус**: 🔍 Требует расследования

### 4. Нет сравнения количества записей
- **Проблема**: Скрипты не сравнивают количество записей до/после операций
- **Последствие**: Невозможно отследить потерю данных
- **Статус**: ❌ Требует исправления

## ⚠️ Важные проблемы

### 5. Отсутствие проверки целостности БД
- **Проблема**: Нет проверки наличия ключевых файлов LevelDB (CURRENT, MANIFEST, .ldb)
- **Последствие**: Восстановление может быть неполным
- **Статус**: ⚠️ Требует улучшения

### 6. Нет информации о MAC-адресе
- **Проблема**: Не выводится MAC-адрес демона, который влияет на загрузку данных
- **Последствие**: Невозможно понять, почему записи не загружаются
- **Статус**: ⚠️ Требует улучшения

### 7. Неструктурированные логи
- **Проблема**: Логи не имеют единого формата, нет пиктограмм
- **Последствие**: Сложно читать и анализировать вывод
- **Статус**: ⚠️ Требует улучшения

### 8. Нет предупреждений о расхождениях
- **Проблема**: Нет предупреждений, если количество записей сильно отличается
- **Последствие**: Потеря данных может остаться незамеченной
- **Статус**: ⚠️ Требует улучшения
