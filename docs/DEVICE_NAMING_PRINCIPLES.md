# Принципы нейминга устройств ReactHome

**Дата анализа:** 11.12.2025  
**Проанализировано устройств:** 1502

## 📊 Статистика использования полей

| Поле | Использование | Назначение |
|------|--------------|------------|
| `title` | **36.7%** | Основное человекочитаемое название |
| `code` | **12.3%** | Техническая метка / структурированный код |
| `name` | **0.0%** | ⚠️ **НЕ ИСПОЛЬЗУЕТСЯ** (устаревшее поле) |

## 🎯 Ключевые выводы

### 1. Поле `name` - УСТАРЕВШЕЕ

**Факт:** Из 1502 устройств **ни одно** не имеет заполненного поля `name`.

**Вывод:** Поле `name` не используется в ReactHome и является устаревшим.

**Рекомендация:** Не полагаться на это поле в коде. Использовать `title` и `code`.

### 2. Поле `title` - ОСНОВНОЕ

**Использование:** 36.7% устройств (551 из 1502)

**Назначение:** Человекочитаемое название устройства для отображения в UI.

**Примеры:**
- `"Освещение"` - простое название
- `"TV Гостиная"` - название с локацией
- `"Подсветка шкафа Гоши"` - детальное описание
- `"R4"`, `"Dim1"` - короткие имена актуаторов

**Характеристики:**
- Может быть пустым (63% устройств без title)
- Может содержать русский текст
- Может быть коротким или длинным
- Приоритет при отображении: **второй** (после code)

### 3. Поле `code` - ТЕХНИЧЕСКАЯ МЕТКА

**Использование:** 12.3% устройств (184 из 1502)

**Назначение:** Структурированный технический код для идентификации.

**Примеры структурированных кодов:**
- `"4.D.L.2"` - формат: `{номер_помещения}.{тип}.{подтип}.{индекс}`
- `"6.D.L.3 Лоджия"` - код с названием помещения
- `"2.D.LED.8 Душ"` - LED освещение с локацией
- `"1.D.LED.4"` - простой структурированный код

**Примеры простых кодов:**
- `"lamp2"` - идентификатор устройства
- `"Р22"` - короткая метка
- `"S4 Коридор"` - код с локацией

**Характеристики:**
- Часто содержит структурированную информацию
- Уникален для каждого устройства
- Может содержать номер помещения, тип, индекс
- Приоритет при отображении: **первый**

## 📋 Наиболее частые комбинации

| Комбинация | Процент | Количество | Описание |
|------------|---------|------------|----------|
| **Пусто** | 58.3% | 875 | Устройства без идентификаторов (используют ID) |
| **Только title** | 29.5% | 443 | Только человекочитаемое название |
| **title + code** | 7.2% | 108 | Оба поля заполнены (оптимально) |
| **Только code** | 5.1% | 76 | Только технический код |
| **Все три поля** | 0.0% | 0 | ⚠️ Никогда не встречается |

## 🎯 Рекомендуемая стратегия отображения

### Приоритет полей

```
code → title → name → id
```

### Обоснование приоритета `code` первым

1. **Структурированность** - code содержит организованную информацию
2. **Уникальность** - code уникален для каждого устройства
3. **Информативность** - code помогает быстро найти устройство в системе
4. **Техническая точность** - code используется в технических схемах

### Алгоритм выбора отображаемого имени

```javascript
function getDisplayName(device) {
  return device.code || device.title || device.name || device.id;
}
```

### Пример использования в коде

```javascript
// ❌ НЕПРАВИЛЬНО (title первым)
const displayName = device.title || device.code || device.name || device.id;

// ✅ ПРАВИЛЬНО (code первым)
const displayName = device.code || device.title || device.name || device.id;
```

## 📝 Примеры из реальной системы

### Устройства с `title + code` (идеальный случай)

```json
{
  "title": "Подсветка шкафа Гоши",
  "code": "1.D.LED.4",
  "name": null
}
```
**Отображение:** `"1.D.LED.4"` (code приоритетнее)

### Устройства только с `title`

```json
{
  "title": "TV Гостиная",
  "code": null,
  "name": null
}
```
**Отображение:** `"TV Гостиная"` (title как fallback)

### Устройства только с `code`

```json
{
  "title": null,
  "code": "S4 Коридор",
  "name": null
}
```
**Отображение:** `"S4 Коридор"` (code есть)

### Устройства без идентификаторов

```json
{
  "title": null,
  "code": null,
  "name": null,
  "id": "68:27:19:e4:49:17"
}
```
**Отображение:** `"68:27:19:e4:49:17"` (используем ID)

## 🔍 Типы устройств по наличию идентификаторов

### Физические устройства (актуаторы, сенсоры)
- Часто имеют `code` (короткий идентификатор: "Dim1", "R4", "lamp2")
- Могут иметь `title` (описательное название)
- **Никогда** не имеют `name`

### Логические устройства (потребители: свет, розетки)
- Часто имеют `title` (описательное название: "Освещение", "TV Гостиная")
- Могут иметь `code` (структурированный код: "4.D.L.2")
- **Никогда** не имеют `name`

### Скрипты и сервисы
- Обычно только `title` (название скрипта)
- Редко имеют `code`

## 💡 Рекомендации для разработки

1. **Не использовать поле `name`** - оно устарело и не заполняется в системе
2. **Приоритет `code` → `title`** - code более информативен для идентификации
3. **Всегда иметь fallback на `id`** - для устройств без идентификаторов
4. **При создании новых устройств:**
   - Обязательно заполнять `title` (человекочитаемое название)
   - По возможности заполнять `code` (технический идентификатор)
   - **Не заполнять `name`** - это поле не используется
