# Логика обновления статуса устройств

## Обзор

Документ описывает логику обновления статуса устройств в скриптах мониторинга состояния щитовых устройств. Описание основано на анализе кода в `scripts/monitor-shield-devices-status-ui-example.js` и `scripts/monitor-shield-devices-status.js`.

## Основные компоненты логики

### 1. Отслеживание изменений состояния (updateDeviceState)

**Назначение:** Определяет, изменилось ли реальное состояние устройства, а не просто получены новые данные.

**Алгоритм:**

1. **Сравнение ключевых полей:**
   - Проверяются поля: `online`, `ip`, `co2`, `temperature`, `humidity`, `illumination`
   - Если хотя бы одно поле изменилось → `stateChanged = true`

2. **Проверка числовых полей с учетом точности:**
   - Для `temperature` и `humidity` учитывается изменение больше 0.1
   - Это предотвращает ложные срабатывания из-за незначительных колебаний

3. **Обновление временных меток:**
   - `lastUpdate` - всегда обновляется при получении данных (даже если ничего не изменилось)
   - `lastStateChange` - обновляется только при реальном изменении состояния

**Пример:**
```javascript
// Первое получение данных
updateDeviceState('device1', { online: true, ip: '192.168.1.1' })
// → lastStateChange = now, lastUpdate = now

// Получены те же данные (ничего не изменилось)
updateDeviceState('device1', { online: true, ip: '192.168.1.1' })
// → lastStateChange = старое значение, lastUpdate = now

// Изменился IP
updateDeviceState('device1', { online: true, ip: '192.168.1.2' })
// → lastStateChange = now, lastUpdate = now
```

### 2. Определение статуса онлайн/оффлайн

#### 2.1 Упрощенная логика (UI-версия)

**Используется в:** `scripts/monitor-shield-devices-status-ui-example.js`

**Алгоритм:**
```javascript
if (state) {
  const isOnline = state.online === true;
  status = isOnline ? '🟢' : '🔴';
} else {
  status = '⚪'; // Ожидание данных
}
```

**Особенности:**
- Используется только поле `state.online`
- Если `state.online === true` → устройство онлайн 🟢
- Если `state.online !== true` (false, undefined, null) → устройство оффлайн 🔴
- Если `state` отсутствует → ожидание данных ⚪

**Недостаток:**
- Устройства, которые отправляют данные (температура, влажность, CO2), но имеют `state.online = false`, будут показаны как оффлайн, хотя фактически работают.

#### 2.2 Улучшенная логика (основная версия)

**Используется в:** `scripts/monitor-shield-devices-status.js`

**Алгоритм:**
```javascript
if (state) {
  let isOnline = state.online === true;
  
  // Если online=false, но устройство отправляет актуальные данные - считаем его онлайн
  if (!isOnline) {
    const dataAge = state.lastUpdate ? Math.floor((Date.now() - state.lastUpdate) / 1000) : null;
    
    const hasRecentData = dataAge !== null && dataAge < 120; // 2 минуты
    const hasSensorData = (state.temperature !== undefined && state.temperature !== null) ||
                         (state.humidity !== undefined && state.humidity !== null) ||
                         (state.co2 !== undefined && state.co2 !== null);
    const hasIp = state.ip && state.ip !== '—';
    
    if (hasRecentData && (hasIp || hasSensorData)) {
      isOnline = true;
    }
  }
  
  status = isOnline ? '🟢' : '🔴';
}
```

**Особенности:**
- Сначала проверяется `state.online === true`
- Если `online = false`, но устройство отправляет актуальные данные → считается онлайн
- Устройство считается работающим, если:
  1. Есть IP-адрес И данные обновлялись недавно (меньше 2 минут)
  2. ИЛИ есть актуальные данные от сенсоров (температура, влажность, CO2) и данные свежие

**Преимущество:**
- Более точное определение статуса устройств
- Устройства, которые фактически работают, но имеют `state.online = false` (например, из-за таймаута discovery), будут показаны как онлайн

### 3. Оптимизация обновлений

#### 3.1 Условное обновление таблицы

**Логика:**
```javascript
if (!this.isNavigating && this.devices.some(d => d.id === deviceId)) {
  this.updateTable();
  this.updateStats();
}
```

**Условия обновления:**
- Устройство видимо (прошло активные фильтры)
- Не идет навигация (флаг `isNavigating === false`)

**Зачем:** Предотвращает мерцание интерфейса при навигации и обновляет только видимые устройства.

#### 3.2 Throttling обновлений

**Логика:**
```javascript
const now = Date.now();
if (now - this.lastUpdateTime < 100) {
  return; // Пропускаем обновление
}
this.lastUpdateTime = now;
```

**Зачем:** Ограничивает частоту обновлений до максимум 10 раз в секунду (100мс), предотвращая перегрузку UI.

#### 3.3 Сохранение позиции курсора

**Логика:**
```javascript
// Сохраняем позицию ПЕРЕД обновлением
let savedSelection = this.selectedIndex;

// ... обновление данных ...

// Восстанавливаем позицию ПОСЛЕ обновления
if (savedSelection >= 0 && savedSelection < validData.length) {
  this.selectedIndex = savedSelection;
}
```

**Зачем:** При обновлении таблицы сохраняется позиция выбранного устройства, чтобы пользователь не терял контекст.

### 4. Обновление статистики

**Алгоритм:**
```javascript
for (const device of this.devices) {
  const state = data?.state;
  if (!state) continue;
  
  const isOnline = state.online === true; // Упрощенная логика
  if (isOnline) {
    online++;
  } else {
    offline++;
  }
}
```

**Особенности:**
- Считается только по отфильтрованным устройствам
- Использует ту же логику определения статуса, что и таблица
- Показывает общее количество устройств в системе и количество показанных

## Сравнение версий

| Аспект | UI-версия | Основная версия |
|--------|----------|-----------------|
| Определение статуса | Упрощенная (только `state.online`) | Улучшенная (учитывает данные сенсоров) |
| Отслеживание изменений | ✅ Есть | ✅ Есть |
| Throttling | ✅ Есть (100мс) | ❌ Нет |
| Сохранение курсора | ✅ Есть | ❌ Не применимо |
| Условное обновление | ✅ Есть | ❌ Нет |

## Рекомендации

1. **Для UI-версии:** Рассмотреть добавление улучшенной логики определения статуса из основной версии для более точного отображения работающих устройств.

2. **Для основной версии:** Рассмотреть добавление throttling для оптимизации производительности при большом количестве устройств.

3. **Унификация:** Создать общую функцию определения статуса, которая будет использоваться в обеих версиях для консистентности.

## Примеры работы логики

### Пример 1: Устройство с актуальными данными, но online=false

**Данные:**
```javascript
state = {
  online: false,
  ip: '192.168.1.10',
  temperature: 25.5,
  lastUpdate: Date.now() - 5000 // 5 секунд назад
}
```

**UI-версия:** 🔴 Оффлайн (используется только `state.online`)
**Основная версия:** 🟢 Онлайн (есть IP и свежие данные от сенсора)

### Пример 2: Устройство без данных

**Данные:**
```javascript
state = null
```

**Обе версии:** ⚪ Ожидание данных

### Пример 3: Устройство с устаревшими данными

**Данные:**
```javascript
state = {
  online: true,
  ip: '192.168.1.10',
  lastUpdate: Date.now() - 180000 // 3 минуты назад
}
```

**Обе версии:** 🟢 Онлайн (но данные устарели)

## Заключение

Логика обновления статуса в UI-версии оптимизирована для интерактивного интерфейса с учетом производительности и удобства навигации. Однако она использует упрощенное определение статуса, которое может показывать работающие устройства как оффлайн. Основная версия использует более точную логику, но менее оптимизирована для частых обновлений.
