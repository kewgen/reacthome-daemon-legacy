# Архитектура допплеров (датчиков движения)

## 🎯 Два вида допплеров

В системе используются **два типа датчиков движения** (допплеров):

### 1️⃣ Встроенные в S4 модули (тип 37 / 0x25)

**Характеристики:**
- Часть сенсорной панели S4
- Встроенный датчик движения
- Встроенный датчик температуры
- **Не требуют bind** (встроены в модуль)
- По одному в каждом помещении с S4

**Количество:** 10 модулей

**Примеры:**
- S4 Душ (`80:98:67:45:dc:23`) - 25.64°C
- S4 Гостиная (`10:71:77:17:61:46`) - 23.54°C
- S4 Спальня (`50:85:48:15:00:f1`) - 25.03°C
- и другие

**Скрипты обработки:**
- Название формата: `s4 doppler handler <помещение>`
- Пример: `s4 doppler handler душ`

### 2️⃣ Отдельные блоки (тип 34 / 0x22)

**Характеристики:**
- Отдельные датчики движения
- Подключаются к DI каналам других устройств
- **Требуют bind** к DI каналу (обычно DI/4)
- Дополнительные датчики в помещениях
- Расширяют покрытие обнаружения движения

**Количество:** 10 датчиков

**Примеры:**
- Душ (`50:f5:4f:e5:9f:5f`)
- Прихожая (`70:97:98:af:d0:43`)
- Коридор лево (`90:79:b7:8f:dc:90`)
- Коридор право (`40:64:06:c0:5d:b5`)
- и другие

**Скрипты обработки:**
- Название формата: `doppler handler <помещение>`
- Пример: `doppler handler душ`

## ⚠️ Обнаруженная проблема

### Все 10 отдельных допплеров НЕ имеют bind!

**Проблема:**
```json
{
  "id": "50:f5:4f:e5:9f:5f",
  "type": 34,  // DOPPLER
  "title": "Душ",
  "bind": null,  // ❌ ОТСУТСТВУЕТ!
  "onDoppler": "8a22c722-dbf9-480f-b647-cab8ffcaf3c1"
}
```

**Ожидается:**
```json
{
  "id": "50:f5:4f:e5:9f:5f",
  "type": 34,
  "title": "Душ",
  "bind": "DEVICE_ID/di/4",  // ✅ Должен быть!
  "onDoppler": "8a22c722-dbf9-480f-b647-cab8ffcaf3c1"
}
```

**Последствия:**
- Неясно, к какому устройству подключен допплер
- Невозможно проверить физическое подключение
- Затруднена диагностика проблем
- Нарушена архитектурная целостность

## 📝 Алгоритм привязки отдельного допплера

### Шаг 1: Определить помещение

```bash
doppler_id="50:f5:4f:e5:9f:5f"
site="Душ"
```

### Шаг 2: Найти контроллер с DI каналами

**Варианты:**
- S4 модуль (тип 37) в том же помещении
- Сенсорный модуль (тип 32) в том же помещении
- Другой контроллер с DI каналами

Для "Душ" возможный вариант: **S4 Душ** (`80:98:67:45:dc:23`)

### Шаг 3: Выбрать свободный DI канал

**Проверить занятость каналов:**
- DI/1, DI/2, DI/3 - ?
- DI/4 - обычно термостат
- DI/5, DI/6, DI/7, DI/8 - ?

**Если DI/4 уже занят термостатом:**
- Использовать другой свободный канал (например, DI/5)

### Шаг 4: Добавить bind

```json
{
  "id": "50:f5:4f:e5:9f:5f",
  "type": 34,
  "title": "Душ",
  "bind": "80:98:67:45:dc:23/di/5",  // ← ДОБАВИТЬ!
  "onDoppler": "8a22c722-dbf9-480f-b647-cab8ffcaf3c1"
}
```

### Шаг 5: Проверить целостность

**Чек-лист:**
- [ ] Допплер и контроллер в одном помещении
- [ ] DI канал свободен (не используется другими устройствами)
- [ ] Bind имеет правильный формат: `<DEVICE_ID>/di/<NUMBER>`
- [ ] Физическое подключение соответствует bind
- [ ] Скрипт onDoppler существует и работает
