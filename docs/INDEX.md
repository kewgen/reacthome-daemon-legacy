# Карта документации

- Проект: reacthome-daemon (GearGames, Жекин Ассистент)
- Назначение: навигация по актуальным документам, правила работы с артефактами.

## Правила
- Секреты — только в `.env`. Не дублировать в документах.
- Скрипты храним в `scripts/`. Перед созданием нового ищем аналог. На запуск разрешение не нужно, на создание — спросить.
- Код в `src/` правим только с разрешения (без него можно трогать только `src/logging`).
- Документацию кладём в `docs/`, отчёты и разовые исследования — в `reports/`.
- После финальных изменений сервисов — перезапускать и сообщать.

## Базовые материалы
- `../README.md` — обзор проекта и ссылки (см. обновлённую версию).
- `COMMIT_PLAN.md` — что включать в коммит для локального запуска, что исключать.
- `REVERT_INSTRUCTIONS.md` — варианты отката изменений.
- `PM2_LOCAL_MONITORING.md` — локальный мониторинг через PM2.
- `DEVICE_NAMING_SPEC.md` — спецификация нейминга устройств (формат `ROOM.ACT.KIND.CH`, пример: `6.D.L.3 Лоджия`).
- `CPU_PROFILING_GUIDE.md` — профилирование CPU на малинке.
- `MEMORY_LEAK_DETECTION.md` — (черновик) как собирать данные по утечкам памяти.
- `MONITOR_PI_QUICK_CHECK.md` — (черновик) быстрая проверка состояния малинки.
- `DOPPLERS.md` — архитектура и параметры допплеров (пороги, обработчики, сценарии).

## Трассировка событий
- `TRACE_CHAIN_ALGORITHM.md` — полный алгоритм построения цепочки срабатывания скриптов по trace_id.
- `TRACE_QUICK_START.md` — краткая инструкция для быстрого старта с примерами команд.
- `TRACING_ALGORITHM_AND_GOALS.md` — цели трассировки и итоговые правила надёжности (анти‑шум, “по потребителю”, toggle on/off).
- `TRACE_REPORT_FORMAT.md` — утвержденный стандарт вывода цепочек событий (одна строка, дельты времени, от источника до потребителя).

## Руководства и runbook’и (предлагаемая структура)
- `runbooks/` — пошаговые инструкции (запуск, мониторинг, профилирование, откат).
- `troubleshooting/` — типовые проблемы (WebSocket, устройства, БД, логи).
- `monitor/` — материалы по `monitor.js` и работе UI мониторинга.
- `security-compliance/` — требования к работе с секретами, доступами, миграциями.
- `architecture/` — схемы компонентов и потоков данных.

## Отчёты и исследования
- Все отчёты в `../reports/`. Сводный список: `../reports/INDEX.md`.
- Свежие материалы по OpenSearch миграции: `../reports/migration-compliance-check.md`, `../reports/opensearch-schema-analysis-2025-12-12.md`.
- Монитор/терминальный UI: `../reports/monitor-improvements-2025-12-10.md`, `../reports/monitor-js-insights-2025-12-10.md`.
- Логи/безопасность: `../reports/logs-audit-summary.md`, `../reports/event-logger-security-audit-2025-12-10.md`.

## Как поддерживать порядок
1) Новая инструкция — в `docs/` с краткой аннотацией в этом индексе.
2) Разовый анализ или аудит — в `reports/` с датой в имени, добавить строку в `reports/INDEX.md`.
3) Ссылки на внешние артефакты — только без секретов; если ссылка протухла, пометить как TODO.
