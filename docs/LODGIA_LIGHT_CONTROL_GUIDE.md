## Проблема

### Исходная ситуация

**Задача:** Реализовать управление освещением в локации "Лоджия" через WebSocket API.

**Проблема:** Команда `ACTION_SITE_LIGHT_ON` с названием локации "Лоджия" не работала - свет не включался.

**Ожидаемое поведение:**
```json
{"type": "ACTION_SITE_LIGHT_ON", "id": "Лоджия"}
```

**Фактическое поведение:** Команда отправлялась, но свет не включался.

## Архитектура системы

### Компоненты системы

1. **WebSocket сервер** (`ws://192.168.88.4:3000`)
   - Локальный сервер на Raspberry Pi
   - Обрабатывает команды управления устройствами
   - Отправляет обновления состояния в реальном времени

2. **State (состояние)**
   - Хранится в памяти процесса
   - Синхронизируется с LevelDB
   - Ключи - UUID устройств/локаций
   - Значения - объекты с данными (payload)

3. **Локации (Sites)**
   - Хранятся по UUID, а не по названию
   - Содержат массивы каналов освещения: `light_220`, `light_LED`, `light_RGB`
   - Могут иметь дочерние локации и родительский проект

4. **Каналы освещения**
   - Привязаны к физическим устройствам через поле `bind`
   - Формат: `{MAC-адрес}/{тип}/{индекс}`
   - Пример: `68:27:19:e4:49:17/dim/3`

### Структура данных локации "Лоджия"

```json
{
  "id": "6b1afa99-9c1e-496e-8bd4-be7e90b71c8d",
  "type": "site",
  "title": "Лоджия",
  "code": "6",
  "light_220": [
    "34731215-af9b-4847-b2f9-67c8940271c0",
    "8828b19b-55b6-4f88-ac6b-20c41b02f1ad"
  ],
  "site": [],
  "project": null
}
```

### Поток выполнения команды

```
1. WebSocket клиент → {"type": "ACTION_SITE_LIGHT_ON", "id": "UUID"}
2. src/websocket/handle.js → run(action)
3. src/controllers/service.js → case ACTION_SITE_LIGHT_ON
4. src/actions/create.js → applySite(id, callback)
5. Для каждого канала в light_220/light_LED/light_RGB:
   - run({ type: ACTION_ON, id: channelId })
6. src/controllers/service.js → case ACTION_ON
7. Находит привязку канала (bind)
8. Отправляет команду на физическое устройство
9. Устройство включает свет
10. Обновление состояния → WebSocket broadcast
```

## Решение

### Правильная команда

**Неправильно:**
```json
{"type": "ACTION_SITE_LIGHT_ON", "id": "Лоджия"}
```

**Правильно:**
```json
{"type": "ACTION_SITE_LIGHT_ON", "id": "6b1afa99-9c1e-496e-8bd4-be7e90b71c8d"}
```

### Реализация в тесте

**Файл:** `tests/integration/test_lodgia_lighting.py`

**Функция поиска локации по названию:**
```python
async def _find_site_by_title(
    websocket: websockets.WebSocketClientProtocol,
    title: str,
    timeout: float,
) -> Optional[str]:
    """Находит UUID локации по её названию (title)."""
    await websocket.send(json.dumps({"type": "list"}))
    # ... поиск в ответах ACTION_SET с payload.title === title
    return site_id
```

**Основной тест:**
```python
# Если передан UUID напрямую - используем его
if _is_uuid(location_title):
    location_id = location_title
else:
    # Ищем по названию
    location_id = await _find_site_by_title(websocket, location_title, timeout)

# Отправляем команду
turn_on = {"type": ACTION_SITE_LIGHT_ON, "id": location_id}
await websocket.send(json.dumps(turn_on))
```

## Оптимизация

### Проблема производительности

**Исходная версия:** ~30 секунд  
**Причина:** Длинные таймауты (15 сек) и отсутствие раннего выхода

### Оптимизации

1. **Пропуск поиска по названию**
   - Если передан UUID напрямую, пропускаем поиск
   - Экономия: ~2-3 секунды

2. **Уменьшение таймаутов**
   - Поиск локации: 15 сек → 2 сек
   - Ожидание обновлений: 15 сек → 2 сек
   - Запрос данных: 15 сек → 2 сек
   - Таймаут на сообщение: 0.5 сек → 0.2 сек

3. **Ранний выход**
   - Прекращаем ожидание после первого обновления канала
   - Экономия: до 2 секунд

4. **Оптимизация логирования**
   - Менее критичные сообщения → DEBUG уровень

### Результаты

| Версия | Время выполнения | Улучшение |
|--------|------------------|-----------|
| Исходная | ~30 секунд | 1x |
| Первая оптимизация | ~3 секунды | 10x |
| Финальная оптимизация | ~0.06 секунды | 500x |

```python
import asyncio
import json
import websockets

async def turn_on_lodgia_light():
    uri = "ws://192.168.88.4:3000"
    location_uuid = "6b1afa99-9c1e-496e-8bd4-be7e90b71c8d"
    
    async with websockets.connect(uri) as websocket:
        # Отправляем команду
        command = {
            "type": "ACTION_SITE_LIGHT_ON",
            "id": location_uuid
        }
        await websocket.send(json.dumps(command))
        
        # Ждём подтверждения (опционально)
        response = await asyncio.wait_for(websocket.recv(), timeout=2.0)
        message = json.loads(response)
        print(f"Получено: {message}")

# Запуск
asyncio.run(turn_on_lodgia_light())
```
