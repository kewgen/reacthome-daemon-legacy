# Правила именования устройств ReactHome

**Дата создания:** 2025-12-19  
**Версия:** 1.0  
**Статус:** Активный

## Обзор

Документ определяет обязательные правила именования устройств, скриптов и других сущностей в системе ReactHome. Правила обеспечивают консистентность, предсказуемость и удобство использования системы.

**Зачем:** Унифицировать нейминг для устранения несогласованностей в коде и улучшения поддерживаемости системы.

### ⚠️ Важно: Разные правила для разных типов устройств

**Физические устройства** (актуаторы, сенсоры):
- Приоритет: `code → title → id`
- `code` приоритетнее (техническая идентификация)

**Логические устройства** (потребители: свет, шторы, полы, вентиляторы):
- Приоритет: `title → code → id`
- `title` обязателен и приоритетнее (используется в UI приложениях!)

**Зачем:** Логические устройства отображаются в мобильных и веб-приложениях, где пользователи видят `title`, а не технический `code`.

## Общие принципы

### 1. Единый источник истины

**Правило:** Приоритет полей должен быть одинаковым во всём коде.

**Приоритет:** `code → title → id`

**Зачем:** Обеспечить предсказуемое отображение имён во всех частях системы.

### 2. Разделение ответственности

**Правило:** `code` и `title` имеют разные назначения и не должны дублировать друг друга.

- `code` — технический идентификатор (для автоматизации, схем, поиска)
- `title` — человекочитаемое название (для UI, отчётов, логов)

### 3. Обратная совместимость

**Правило:** Поле `name` считается устаревшим и не должно использоваться в новом коде.

**Зачем:** Поле `name` не заполняется в системе (0% устройств), проверка его только замедляет код.

## Поля идентификации

### Поле `code`

**Назначение:** Технический структурированный идентификатор устройства.

**Формат:** Структурированный код с разделителями.

**Ограничения:**
- ✅ Только латиница (a-z, A-Z)
- ✅ Цифры (0-9)
- ✅ Точки (`.`) как разделители
- ✅ Подчёркивания (`_`) для связки слов
- ✅ Дефисы (`-`) для диапазонов
- ❌ Пробелы запрещены
- ❌ Кириллица запрещена
- ❌ Специальные символы запрещены

**Рекомендуемые форматы:**

1. **Структурированный код помещений:**
   ```
   {номер_помещения}.{тип}.{подтип}.{индекс}
   ```
   Примеры: `4.D.L.2`, `6.D.LED.3`, `1.D.L.4`

2. **Короткий идентификатор:**
   ```
   {тип}{номер}
   ```
   Примеры: `R12`, `Dim4`, `S4`, `DO8`

3. **Идентификатор с локацией:**
   ```
   {тип}{номер}_{локация}
   ```
   Примеры: `S4_Corridor`, `R1_LivingRoom`

**Когда использовать:**
- Физические устройства (актуаторы, сенсоры)
- Логические устройства (потребители) с привязкой к помещению
- Когда нужна структурированная идентификация

**Примеры правильного использования:**

```json
{
  "code": "4.D.L.2",
  "title": "Подсветка шкафа Гоши"
}
```

```json
{
  "code": "R12",
  "title": "Реле модуль 12"
}
```

**Примеры неправильного использования:**

```json
// ❌ Кириллица в code
{
  "code": "Свет Лоджия",
  "title": "Свет Лоджия"
}

// ❌ Пробелы в code
{
  "code": "6.D.L.3 Лоджия",
  "title": "Лоджия спот"
}

// ❌ Дублирование с title
{
  "code": "TV Гостиная",
  "title": "TV Гостиная"
}
```

### Поле `title`

**Назначение:** Человекочитаемое название для отображения в UI.

**Формат:** Свободный текст.

**Ограничения:**
- ✅ Любые символы (включая кириллицу)
- ✅ Пробелы разрешены
- ✅ Специальные символы разрешены (кроме управляющих)
- ❌ Не должен быть техническим кодом (это для `code`)

**Когда использовать:**
- Всегда для логических устройств (потребители)
- Рекомендуется для физических устройств
- Обязательно для скриптов

**Примеры правильного использования:**

```json
{
  "code": "4.D.L.2",
  "title": "Подсветка шкафа Гоши"
}
```

```json
{
  "code": null,
  "title": "TV Гостиная"
}
```

**Примеры неправильного использования:**

```json
// ❌ Технический код в title
{
  "code": "Лоджия спот",
  "title": "6.D.L.3 Toggle"
}

// ❌ Дублирование с code
{
  "code": "R12",
  "title": "R12"
}
```

### Поле `name` (устаревшее)

**Статус:** ⚠️ УСТАРЕВШЕЕ

**Правило:** Не использовать в новом коде. Не проверять в приоритете полей.

**Зачем:** Поле не заполняется в системе (0% устройств из 1502).

**Миграция:** Существующий код должен быть обновлён для удаления проверки `name` из приоритета.

## Правила для устройств

**Важно:** Правила именования для физических и логических устройств **отличаются**, так как они используются в разных контекстах.

### Физические устройства (актуаторы, сенсоры)

**Назначение:** Технические устройства в щитовой или конечные устройства управления.

**Обязательные поля:**
- `title` — рекомендуется (для отображения в UI и логов)
- `code` — опционально (для структурированной идентификации)

**Приоритет отображения:** `code → title → id`

**Зачем:** Для физических устройств технический `code` приоритетнее, так как используется в схемах и автоматизации.

**Примеры:**

```json
// ✅ Идеальный случай: оба поля заполнены
{
  "id": "68:27:19:e4:49:17",
  "type": 161,
  "code": "R12",
  "title": "Реле модуль 12 каналов",
  "online": true
}
```

```json
// ✅ Минимальный случай: только title
{
  "id": "40:64:06:c0:5d:b5",
  "type": 10,
  "code": null,
  "title": "Диммер зал",
  "online": true
}
```

```json
// ⚠️ Допустимо: только code (не рекомендуется)
{
  "id": "90:89:d3:f1:2d:0f",
  "type": 1,
  "code": "S4",
  "title": null,
  "online": true
}
```

### Логические устройства (потребители)

**Назначение:** Устройства, управляемые пользователем через UI приложения (свет, шторы, тёплый пол, вентиляторы).

**Обязательные поля:**
- `title` — **ОБЯЗАТЕЛЬНО** (используется в UI приложениях)
- `code` — опционально (для структурированной идентификации)

**Приоритет отображения:** `title → code → id`

**Зачем:** Для логических устройств `title` критически важен, так как он отображается в мобильных и веб-приложениях для управления светом, шторами, тёплым полом, вентиляторами. Пользователи видят именно `title`, а не технический `code`.

**Типы логических устройств:**
- `light_220`, `light_LED`, `light_RGB` — освещение
- `curtains`, `blind`, `roller` — шторы и жалюзи
- `warm_floor` — тёплый пол
- `fan` — вентиляторы
- `socket_220` — розетки
- `thermostat`, `hygrostat`, `co2_stat` — регуляторы
- `TV`, `AC`, `boiler`, `pump` — бытовая техника

**Важно:** Если `title` отсутствует, пользователь увидит технический `code` или UUID, что ухудшает UX.

**Примеры:**


```json
// ❌ НЕПРАВИЛЬНО: только code без title
// В UI приложении отобразится технический код "4.D.L.2" - плохой UX!

  "id": "c3d4e5f6-a7b8-9012-cdef-123456789012",
```

## Правила для скриптов

- `title` — обязательно (для отображения в UI)

## Приоритет полей

### Разные алгоритмы для разных типов устройств

**Правило:** Приоритет полей зависит от типа устройства.

**Зачем:** Физические устройства используются в технических контекстах (схемы, автоматизация), а логические — в UI приложениях (управление пользователем).

### Алгоритм для физических устройств

**Приоритет:** `code → title → id`

**Использование:** Актуаторы, сенсоры, конечные устройства управления.

```javascript
/**
 * Получает отображаемое имя физического устройства
 * 
 * Зачем: Для физических устройств технический code приоритетнее
 * 
 * @param {Object} device - Объект с полями code, title, id, type (числовой)
 * @returns {string} Отображаемое имя
 */
function getPhysicalDeviceName(device) {
  if (!device || typeof device !== 'object') {
    return 'Без названия';
  }
  
  // Физические устройства имеют числовой type
  if (typeof device.type === 'number') {
    // Приоритет: code → title → id
    return device.code || device.title || device.id || 'Без названия';
  }
  
  // Если не физическое, используем алгоритм для логических
  return getLogicalDeviceName(device);
}
```

### Алгоритм для логических устройств (потребителей)

**Приоритет:** `title → code → id`

**Использование:** Свет, шторы, тёплый пол, вентиляторы, розетки и другие устройства, управляемые через UI.

```javascript
/**
 * Получает отображаемое имя логического устройства (потребителя)
 * 
 * Зачем: Для логических устройств title критически важен для UI приложений
 * 
 * @param {Object} device - Объект с полями code, title, id, type (строковый)
 * @returns {string} Отображаемое имя
 */
function getLogicalDeviceName(device) {
  if (!device || typeof device !== 'object') {
    return 'Без названия';
  }
  
  // Логические устройства имеют строковый type
  if (typeof device.type === 'string') {
    // Приоритет: title → code → id
    // title обязателен для UI приложений!
    return device.title || device.code || device.id || 'Без названия';
  }
  
  // Если не логическое, используем алгоритм для физических
  return getPhysicalDeviceName(device);
}
```

### Универсальный алгоритм (с автоопределением типа)

**Зачем:** Для случаев, когда тип устройства неизвестен заранее.

```javascript
/**
 * Получает отображаемое имя устройства с автоопределением типа
 * 
 * Зачем: Единая функция для всех случаев с автоматическим выбором алгоритма
 * 
 * @param {Object} device - Объект с полями code, title, id, type
 * @returns {string} Отображаемое имя
 */
function getDisplayName(device) {
  if (!device || typeof device !== 'object') {
    return 'Без названия';
  }
  
  // Определяем тип устройства по полю type
  const isPhysical = typeof device.type === 'number';
  const isLogical = typeof device.type === 'string' && 
    ['light_220', 'light_LED', 'light_RGB', 'socket_220', 'curtains', 
     'blind', 'roller', 'warm_floor', 'fan', 'thermostat', 'hygrostat', 
     'co2_stat', 'TV', 'AC', 'boiler', 'pump'].includes(device.type);
  
  if (isLogical) {
    // Логические устройства: title → code → id
    return device.title || device.code || device.id || 'Без названия';
  } else if (isPhysical) {
    // Физические устройства: code → title → id
    return device.code || device.title || device.id || 'Без названия';
  } else {
    // По умолчанию (скрипты, помещения): code → title → id
    return device.code || device.title || device.id || 'Без названия';
  }
}
```

### Использование в коде

**✅ ПРАВИЛЬНО:**

```javascript
// Для физических устройств (числовой type)
if (typeof device.type === 'number') {
  const displayName = device.code || device.title || device.id || 'Без названия';
}

// Для логических устройств (строковый type)
if (typeof device.type === 'string') {
  const displayName = device.title || device.code || device.id || 'Без названия';
}

// Универсальная функция с автоопределением
const displayName = getDisplayName(device);
```

**❌ НЕПРАВИЛЬНО:**

```javascript
// ❌ name первым (поле не используется)
const displayName = device.name || device.title || device.code || 'Без названия';

// ❌ Одинаковый приоритет для всех типов устройств
// Для логических устройств title должен быть первым!
const displayName = device.code || device.title || device.id || 'Без названия';

// ❌ Не учитывается тип устройства
const nameA = a.title || a.code || a.name || '';  // Неправильно для физических
const nameB = b.code || b.title || b.id || '';    // Неправильно для логических
```

### Специальные случаи

**UI приложения (мобильные, веб):**

```javascript
// Для логических устройств в UI приложениях
// Зачем: Пользователи видят title, а не технический code
function getUIDisplayName(device) {
  if (typeof device.type === 'string') {
    // Логические устройства: title обязателен!
    if (!device.title) {
      console.warn(`Устройство ${device.id} не имеет title - плохой UX!`);
    }
    return device.title || device.code || device.id || 'Без названия';
  }
  // Физические устройства в UI используются редко
  return device.code || device.title || device.id || 'Без названия';
}
```

**Логи и отчёты:**

```javascript
// Для логов можно использовать технический code
// Зачем: В логах важна техническая идентификация
function getLogName(device) {
  if (typeof device.type === 'number') {
    // Физические: code приоритетнее
    return device.code || device.title || device.id || 'Без названия';
  }
  // Логические: всё равно title для читаемости
  return device.title || device.code || device.id || 'Без названия';
}
```

### Функция для получения человекочитаемого имени

**Зачем:** Для логов и отчётов, где нужен полный путь идентификации.

```javascript
/**
 * Получает полное человекочитаемое имя (code/title/name)
 * 
 * Зачем: Для логов и отчётов, где нужна полная информация
 * 
 * @param {Object} obj - Объект с полями code, title, name
 * @returns {string} Полное имя через "/"
 */
function getHumanName(obj) {
  if (!obj || typeof obj !== 'object') {
    return null;
  }
  
  const parts = [];
  if (obj.code) parts.push(obj.code);
  if (obj.title) parts.push(obj.title);
  // name не добавляем - поле устаревшее
  
  return parts.length > 0 ? parts.join('/') : null;
}
```

## Валидация

### Правила валидации при создании/обновлении

**Правило:** При создании или обновлении устройства/скрипта должна выполняться валидация полей.

**Реализация:**

```javascript
/**
 * Валидирует поля именования устройства/скрипта
 * 
 * Зачем: Обеспечить соответствие правилам именования
 * 
 * @param {Object} obj - Объект с полями code, title
 * @returns {Object} { valid: boolean, errors: string[] }
 */
function validateNaming(obj) {
  const errors = [];
  
  // Валидация code
  if (obj.code) {
    // Проверка формата: только латиница, цифры, точки, подчёркивания, дефисы
    if (!/^[a-zA-Z0-9._-]+$/.test(obj.code)) {
      errors.push('code должен содержать только латиницу, цифры, точки, подчёркивания и дефисы');
    }
    
    // Проверка на пробелы
    if (/\s/.test(obj.code)) {
      errors.push('code не должен содержать пробелы');
    }
    
    // Проверка на кириллицу
    if (/[а-яА-ЯёЁ]/.test(obj.code)) {
      errors.push('code не должен содержать кириллицу');
    }
  }
  
  // Валидация дублирования
  if (obj.code && obj.title && obj.code === obj.title) {
    errors.push('code и title не должны быть одинаковыми (дублирование информации)');
  }
  
  // Валидация title (обязателен для логических устройств)
  if (obj.type && typeof obj.type === 'string') {
    // Логические устройства должны иметь title для UI приложений
    const logicalDeviceTypes = [
      'light_220', 'light_LED', 'light_RGB', 
      'socket_220', 'curtains', 'blind', 'roller',
      'warm_floor', 'fan', 'thermostat', 'hygrostat',
      'co2_stat', 'TV', 'AC', 'boiler', 'pump'
    ];
    
    if (logicalDeviceTypes.includes(obj.type) && !obj.title) {
      errors.push(`title обязателен для логических устройств типа "${obj.type}" (используется в UI приложениях)`);
    }
  }
  
  return {
    valid: errors.length === 0,
    errors
  };
}
```

### Использование валидации

```javascript
// При создании/обновлении устройства
const validation = validateNaming(device);
if (!validation.valid) {
  console.error('Ошибки валидации именования:', validation.errors);
  // Обработка ошибок
}
```

## Примеры

### Пример 1: Физическое устройство (реле)

```json
{
  "id": "68:27:19:e4:49:17",
  "type": 161,
  "code": "R12",
  "title": "Реле модуль 12 каналов",
  "online": true,
  "ip": "172.16.0.5"
}
```

**Отображение:** `"R12"` (code приоритетнее)

**Логирование:** `"R12/Реле модуль 12 каналов"` (через getHumanName)

### Пример 2: Логическое устройство (свет)

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "type": "light_220",
  "code": "4.D.L.2",
  "title": "Подсветка шкафа Гоши",
  "site": "6b1afa99-9c1e-496e-8bd4-be7e90b71c8d",
  "bind": "68:27:19:e4:49:17/do/1"
}
```

**Отображение в UI:** `"Подсветка шкафа Гоши"` (title приоритетнее для логических устройств)

**Отображение в логах:** `"Подсветка шкафа Гоши"` (title для читаемости)

**Логирование:** `"4.D.L.2/Подсветка шкафа Гоши"` (через getHumanName)

### Пример 3: Скрипт

```json
{
  "type": "script",
  "id": "d21fb8e9-e1da-45b0-a9d2-0ab4cb775a6a",
  "title": "6.D.L.3 Toggle",
  "code": "Лоджия спот",
  "action": ["..."]
}
```

**Отображение:** `"Лоджия спот"` (code приоритетнее, даже если title технический)

**Логирование:** `"Лоджия спот/6.D.L.3 Toggle"` (через getHumanName)

### Пример 4: Физическое устройство без code

```json
{
  "id": "40:64:06:c0:5d:b5",
  "type": 10,
  "code": null,
  "title": "Диммер зал",
  "online": true
}
```

**Отображение:** `"Диммер зал"` (title как fallback для физических устройств)

**Логирование:** `"Диммер зал"` (через getHumanName)

### Пример 5: Логическое устройство без title (ОШИБКА!)

```json
{
  "id": "c3d4e5f6-a7b8-9012-cdef-123456789012",
  "type": "light_LED",
  "code": "4.D.L.2",
  "title": null,  // ❌ ОШИБКА!
  "site": "6b1afa99-9c1e-496e-8bd4-be7e90b71c8d"
}
```

**Отображение в UI:** `"4.D.L.2"` (технический code - плохой UX!)

**Проблема:** Пользователь увидит технический код вместо понятного названия.

**Решение:** Обязательно заполнить `title` для логических устройств!

### Пример 6: Помещение

```json
{
  "type": "site",
  "id": "6b1afa99-9c1e-496e-8bd4-be7e90b71c8d",
  "code": "6",
  "title": "Лоджия"
}
```

**Отображение:** `"6"` (code приоритетнее)

**Логирование:** `"6/Лоджия"` (через getHumanName)
