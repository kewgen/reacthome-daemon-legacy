## Обзор

**Reacthome Daemon** — это серверный компонент системы умного дома, который централизует управление устройствами через различные протоколы связи (RBUS, Modbus, ArtNet, DALI и др.). Демон обеспечивает двустороннюю связь между локальными и удалёнными клиентами, устройствами и облачными сервисами, предоставляя единый API для управления инфраструктурой умного дома.

**Версия**: 5.1  
**Язык**: JavaScript (Node.js)  
**Лицензия**: MIT

---

## Предназначение

Демон решает следующие задачи:

1. **Управление устройствами** — обнаружение, инициализация и управление устройствами через UDP, последовательные порты и TCP-соединения
2. **Синхронизация состояния** — поддержание актуального состояния всех устройств в памяти (in-memory) с персистентным хранилищем в LevelDB
3. **Маршрутизация команд** — распределение команд от UI, скриптов и расписаний к соответствующим драйверам и устройствам
4. **Сетевые сервисы** — предоставление локального WebSocket API и подключение к удалённому шлюзу для доступа извне
5. **Интеграция с медиа** — поддержка видеозвонков через Janus и SIP, управление камерами и терминалами
6. **Уведомления** — отправка push-уведомлений через Apple Push Notification и Firebase Cloud Messaging
7. **Автоматизация** — выполнение скриптов, расписаний, таймеров и сценариев на основе событий устройств

### Компоненты системы

#### 1. Точка входа (`daemon.js`)

Основной файл демона выполняет инициализацию в следующей последовательности:

1. **Обработка исключений** — перехватывает необработанные ошибки для предотвращения падения
2. **Загрузка состояния** — восстанавливает все записи из LevelDB в память
3. **Инициализация MAC** — генерирует или восстанавливает уникальный идентификатор демона
4. **Создание директорий** — автоматически создаёт `var/assets`, `var/tmp`, `var/db`
5. **Запуск контроллеров** — активирует device, service, cpu, weather
6. **Инициализация драйверов** — сканирует проект и создаёт экземпляры драйверов устройств
7. **Сетевые сервисы** — запускает discovery (мультикаст), WebSocket-сервер, Janus, SIP
8. **Восстановление задач** — активирует запланированные таймеры, расписания и скрипты
9. **Стартовый сценарий** — выполняет `onStart` проект после 2-секундной задержки

#### 2. Управление состоянием

##### In-Memory State (`src/controllers/state.js`)

Быстрый доступ к текущему состоянию всех сущностей системы:

- **Хранилище**: обычный JavaScript объект `{}`
- **Операции**: `get(id)`, `set(id, payload)`, `list()`, `assets()`
- **Инициализация**: загружается из LevelDB при старте через `state.init(init)`
- **Структура записей**: все объекты содержат поле `timestamp` для отслеживания изменений

##### Персистентное хранилище (`src/db.js`)

LevelDB для долговременного хранения:

- **Расположение**: `var/db`
- **Кодировка**: JSON
- **Операции**: асинхронные через `db.put()`, `db.iterator()`
- **Ключи**: идентификаторы сущностей (MAC, ID устройств, проекты, скрипты)

##### Действия над состоянием (`src/actions/`)

**create.js** — базовые операции CRUD:

- `get(id)` — получение состояния из памяти
- `set(id, payload)` — обновление с проверкой на дубликаты (fast-deep-equal)
- `add(id, ref, value)` — добавление элемента в массив
- `del(id, ref, value)` — удаление элемента из массива
- `makeBind(id, ref, value, bind)` — создание двусторонней связи между сущностями
- `addBind(id, ref, value, bind)` — добавление связи с очисткой предыдущих
- `applySite(id, action)` — рекурсивное применение действия ко всем сайтам проекта

**count.js** — подсчёт активных устройств:

- `count(id)` — общий счётчик
- `count_on(id)` — включённые устройства
- `count_off(id)` — выключенные устройства

**status.js** — управление онлайн-статусом:

- `online(id, payload)` — установка устройства в онлайн с IP и типом
- `offline(id)` — перевод устройства в оффлайн

**firmware.js** — обновление прошивок:

- `pendingFirmware(id)` — пометка устройства как ожидающего обновления
- `updateFirmware(id, path)` — инициирование процесса обновления

**init.js** — инициализация устройств:

- `initialize(id)` — запуск процесса инициализации устройства
- `initialized(id)` — подтверждение завершения инициализации

#### 3. Контроллеры

##### Device Controller (`src/controllers/device.js`)

Управление жизненным циклом устройств:

- **Обнаружение** — обработка пакетов `ACTION_DISCOVERY` и `ACTION_READY`
- **Онлайн-статус** — отслеживание подключённых устройств через IP-адреса
- **События устройств** — обработка `ACTION_DI`, `ACTION_DO`, `ACTION_TEMPERATURE`, `ACTION_HUMIDITY`, `ACTION_CO2` и др.
- **Обработка ошибок** — разбор `ACTION_ERROR` для различных типов устройств
- **RBUS-маршрутизация** — пересылка команд через концентраторы (Smart TOP/Bottom)

**Обрабатываемые типы устройств** (из `constants.js`):

- Датчики: `DEVICE_TYPE_SENSOR4`, `DEVICE_TYPE_SENSOR6`, `DEVICE_TYPE_THI`, `DEVICE_TYPE_DOPPLER`
- Реле: `DEVICE_TYPE_RELAY_2`, `DEVICE_TYPE_RELAY_6`, `DEVICE_TYPE_RELAY_12`, `DEVICE_TYPE_RELAY_24`
- Диммеры: `DEVICE_TYPE_DIM4`, `DEVICE_TYPE_DIM8`, `DEVICE_TYPE_DIM_12_LED_RS`
- Smart-панели: `DEVICE_TYPE_SMART_TOP_A6P`, `DEVICE_TYPE_SMART_TOP_G4D` и др.
- Специализированные: `DEVICE_TYPE_PLC`, `DEVICE_TYPE_IR_RECEIVER`, `DEVICE_TYPE_SMART_4G`

##### Service Controller (`src/controllers/service.js`)

Исполнитель команд и автоматизации:

- **Обработка действий** — огромный `switch(action.type)` для всех типов команд
- **Управление устройствами** — `ACTION_DO`, `ACTION_ON`, `ACTION_OFF`, `ACTION_DIM`, `ACTION_RGB`
- **Расписания и таймеры** — `ACTION_TIMER_START/STOP`, `ACTION_SCHEDULE_START/STOP`
- **Скрипты** — `ACTION_SCRIPT_RUN` для выполнения пользовательских сценариев
- **Термостаты и регуляторы** — `ACTION_THERMOSTAT_HANDLE`, `ACTION_HYGROSTAT_HANDLE`, `ACTION_CO2_STAT_HANDLE`
- **Управление сайтами** — `ACTION_SITE_LIGHT_ON/OFF` для группового управления освещением
- **Интеграция с драйверами** — делегирование специфических команд в `drivers.run()`

**Особенности**:

- Поддержка версионности устройств (проверка `major`, `minor` для совместимости)
- Очередь команд с интервалом 3 мс для предотвращения перегрузки сети
- Обработка timeout, групп и других расширенных параметров

##### State Controller (`src/controllers/state.js`)

Оперативное хранилище состояний:

- `init(s)` — инициализация из загруженных данных
- `get(id)` — получение состояния сущности
- `set(id, payload)` — обновление состояния (слияние с существующим)
- `list()` — список всех сущностей с временными метками
- `assets()` — извлечение всех используемых изображений

##### CPU Controller (`src/controllers/cpu.js`)

Мониторинг системных ресурсов:

- Отслеживание загрузки CPU
- Периодическая публикация метрик в состояние системы

##### Weather Controller (`src/controllers/weather.js`)

Агрегация внешних данных о погоде:

- Получение данных из внешних API
- Обновление состояния проекта с погодной информацией

#### 4. Драйверы устройств

- `manage()` — инициализация и поддержание соединений
- `handle()` — обработка входящих сообщений от устройств
- `run(action)` — выполнение команд

**HVAC (отопление, вентиляция, кондиционирование)**:

**Шахты вентиляции**:

**Управление драйверами** (`src/drivers/driver.js`):

- `drivers.manage()` — сканирует проект, находит все устройства-драйверы и создаёт их экземпляры

- `drivers.run(action)` — выполняет команду через нужный драйвер

#### 5. Сетевые сервисы

##### Discovery (`src/discovery.js`)

Мультикаст-объявления для локального обнаружения демонов:

- **Группа**: `224.0.0.2` (клиенты)
- **Порт**: `2021` (CLIENT_PORT)
- **Интервал**: каждые 10 секунд
- **Формат**: JSON с `id`, `type: "discovery"`, `payload`
- **Цель**: позволяет клиентам находить доступные демоны в локальной сети

##### WebSocket (`src/websocket/`)

**Локальный сервер** (`server.js`):

- **Порт**: `3000`
- **Протокол**: стандартный WebSocket (без подпротоколов)
- **Сессии**: каждое подключение получает UUID-сессию
- **Регистрация**: сессии сохраняются в `peers` Map

**Удалённый шлюз** (`gate.js`):

- **URL**: `wss://gate.reacthome.net/<mac>`
- **Протокол**: `"listen"`
- **Формат сообщений**: `{uuid36}{json}` — первые 36 символов UUID, затем JSON
- **Keepalive**: ping каждые 1000 мс, таймаут 2 секунды
- **Переподключение**: автоматическое при разрыве соединения

**Обработка команд** (`handle.js`):

Поддерживаемые типы команд описаны в README.md в разделе "Работа по вебсокету".

**Peer-менеджмент** (`peer.js`):

- `peers` — Map сессий с объектами `{ session, online, state, timestamp, send() }`
- `send(session, message)` — отправка сообщения конкретной сессии
- `broadcast(message, ignore)` — рассылка всем сессиям, кроме указанной

##### Janus (`src/janus/`)

Интеграция с Janus WebRTC Server для видеозвонков:

- Поддержка ICE-кандидатов (`CANDIDATE`)
- Keepalive для поддержания сессий (`KEEPALIVE`)
- Маршрутизация медиа-потоков

##### SIP (`src/sip/`)

Обработка SIP-протокола для телефонии:

- `ACK` — подтверждение звонков
- `BYE` — завершение звонков
- `INFO` — информационные сообщения
- Интеграция с управлением камерами

##### Camera (`src/camera/`)

Управление видеопотоками:

- `WATCH` — начало просмотра
- `START` — запуск потока
- `STOP` — остановка потока
- `PAUSE` — пауза потока

#### 6. RBUS — шина устройств

RBUS — проприетарный протокол для связи с устройствами через последовательные порты и UDP.

##### Архитектура RBUS

**Сериальный адаптер** (`src/rbus/serial/`):

- Открывает последовательный порт (например, `/dev/ttyAMA0`)
- Преобразует пакеты RBUS в UDP-пакеты
- Обрабатывает входящие UDP-пакеты и отправляет их в последовательный порт

**UDP-адаптер** (`src/rbus/udp/`):

- Создаёт UDP-сокет для общения с устройствами через IP
- Обрабатывает входящие пакеты от устройств

**CRC-проверка** (`src/rbus/crc.js`):

- Реализует проверку целостности пакетов через CRC16

**Инициализация** (`rbus.js`):

Утилитарный скрипт для создания RBUS-моста:
- Извлекает MAC из сетевого интерфейса
- Запускает `rbus(mac, host, path)` для связки UDP и последовательного порта

##### Формат пакетов RBUS

- **Заголовок**: MAC-адрес устройства (6 байт)
- **Действие**: код действия (1 байт)
- **Полезная нагрузка**: зависит от типа действия

**Специальные действия**:
- `ACTION_RBUS_TRANSMIT` (0xA1) — пересылка через концентратор
  - Формат: `[0xA1, mac[6], port, address, ...data]`
- `ACTION_SMART_TOP` (0x30) — команда для Smart TOP через Bottom

#### 7. UDP Socket для устройств

##### Создание сокета (`src/sockets/socket.js`)

Обёртка над `dgram.createSocket('udp4')`:

- **Параметры**:
  - `discovery` — функция генерации discovery-пакетов
  - `interval` — интервал отправки discovery (10 секунд)
  - `port` — порт для отправки (2017)
  - `listen` — порт для прослушивания (2016)
  - `multicast` — интерфейс для мультикаста (`172.16.0.1`)

- **Операции**:
  - `send(packet, ip)` — отправка UDP-пакета на указанный IP
  - `handle(handler)` — регистрация обработчика входящих пакетов

##### Устройства (`src/sockets/device.js`)

Специализированный сокет для работы с устройствами:

- **Discovery** — отправка `ACTION_DISCOVERY` в группу `224.0.0.1` каждые 10 секунд
- **Очередь команд** — все операции проходят через очередь с интервалом 3 мс
- **RBUS-отправка** — `device.sendRBUS(data, id)` для маршрутизации через концентраторы
- **Smart TOP** — `device.sendTOP(data, id)` для управления верхними панелями

#### 8. Уведомления (`src/notification/`)

**APN** (`apn.js`) — Apple Push Notification:

- Интеграция с библиотекой `apn`
- Отправка уведомлений на iOS-устройства

**Firebase** (`firebase.js`) — Firebase Cloud Messaging:

- Использование `firebase-admin`
- Отправка уведомлений на Android-устройства

**Токены** (`token.js`):

- Регистрация push-токенов пользователей
- Привязка токенов к WebSocket-сессиям
- Очистка токенов при отключении

**Уведомления** (`notify.js`, `service.js`):

- Обёртка для отправки уведомлений
- Интеграция с системами APN и FCM

#### 9. Ассистент (`src/assist/`)

Обработка естественного языка:

- **Levenshtein** (`levenshtein.js`) — алгоритм поиска наиболее похожих команд
- **Case** (`case.js`) — обработка текстовых команд
- **Языковая поддержка** (`lang/ru.js`) — русские команды и синонимы
- **Инициализация** (`index.js`) — загрузка словаря и подготовка обработчика

**Использование**:

- Команда `ACTION_ASSIST` через WebSocket
- Обработка текстовых запросов пользователей
- Поиск соответствующих действий устройств

#### 10. Терминал (`src/terminal/`)

Интеграция с `node-pty` для терминального доступа:

- **Создание PTY** — порождение псевдотерминала (`bash` или `powershell.exe`)
- **Обработка команд** — отправка данных в PTY, получение вывода
- **Изменение размера** — поддержка изменения размеров терминала (`rows`, `cols`)
- **Формат** — команды и ответы через WebSocket с типом `PTY`

## Протоколы и форматы данных

### UDP-протокол для устройств

#### Discovery-пакет

**Отправка демоном**:
```
[ACTION_DISCOVERY (0xF0), IP_BE[4], PORT_BE[2]]
```

**Пример**:
- IP: `172.16.0.1` → `0xAC100001`
- Порт: `2016` → `0x07E0`
- Полный пакет: `[0xF0, 0xAC, 0x10, 0x00, 0x01, 0x07, 0xE0]`

#### Ответ устройства

**Структура**:
```
[MAC[6], ACTION[1], DATA[...]]
```

**ACTION_DISCOVERY/READY**:
```
[MAC[6], 0xF0/0xF1, TYPE[1], MAJOR[1], MINOR[1]]
```

#### Команды управления

**ACTION_DO** (0x00):
```
[0x00, INDEX[1], VALUE[1], ...опциональные_параметры]
```

Опциональные параметры:
- **Timeout**: `[2, TIMEOUT_LE[4]]` — задержка отключения
- **Group**: `[3, GROUP_ID[1]]` — привязка к группе

**ACTION_RGB** (0xE0):
```
[0xE0, INDEX[1], R[1], G[1], B[1]]
```

**ACTION_DIMMER** (0xD0):
```
[0xD0, INDEX[1], COMMAND[1], VALUE[1], ...]
```

### WebSocket-протокол

#### Формат сообщений

**Локальное подключение**:
```json
{"type":"ACTION_SET","id":"device/relay/1","payload":{"value":1}}

**Удалённое подключение (через шлюз)**:
```
123e4567-e89b-12d3-a456-426614174000{"type":"ACTION_SET","id":"device/relay/1","payload":{"value":1}}

## Жизненный цикл системы

### Запуск демона

1. **Инициализация файловой системы** — создание `var/assets`, `var/tmp`, `var/db`
2. **Загрузка базы данных** — восстановление всех записей из LevelDB
3. **Генерация/восстановление MAC** — уникальный идентификатор демона
4. **Инициализация контроллеров** — подготовка state, device, service, cpu, weather
5. **Запуск драйверов** — сканирование проекта и создание экземпляров драйверов
6. **Сетевые сервисы** — запуск discovery, WebSocket, Janus, SIP
7. **Восстановление задач** — активация таймеров, расписаний, скриптов
8. **Стартовый сценарий** — выполнение `project.onStart` после 2 секунд

### Работа демона

1. **Обнаружение устройств** — каждые 10 секунд отправка discovery-пакетов
2. **Обработка событий** — входящие пакеты от устройств обрабатываются в device controller
3. **Обновление состояния** — все изменения синхронизируются с LevelDB и рассылаются через WebSocket
4. **Выполнение команд** — команды от UI/скриптов обрабатываются через service controller
5. **Автоматизация** — таймеры, расписания и скрипты выполняются автоматически
6. **Мониторинг** — отслеживание ресурсов CPU и состояния системы

### Остановка демона

- Graceful shutdown через сигналы процесса
- Сохранение финального состояния в LevelDB (при корректном завершении)
- Закрытие всех сетевых соединений

## Безопасность

### Текущие меры

1. **Локальный WebSocket** — доступен только внутри сети (порт 3000)
2. **Удалённый доступ** — через защищённый шлюз `wss://gate.reacthome.net`
3. **UUID-сессии** — уникальные идентификаторы для каждого подключения
4. **Валидация JSON** — обработка некорректных сообщений без падения

### Рекомендации

1. **Firewall** — ограничение доступа к портам демона
2. **VPN** — использование VPN для удалённого доступа
3. **Аутентификация** — добавление токенов/ключей для WebSocket-подключений
4. **Шифрование** — использование TLS для локального WebSocket (wss://)

---

## Масштабируемость и производительность

### Оптимизации

1. **In-Memory State** — быстрый доступ к состоянию без обращений к БД
2. **Очередь команд** — интервал 3 мс предотвращает перегрузку сети
3. **Асинхронная БД** — LevelDB не блокирует основной поток
4. **Broadcast-рассылка** — эффективная синхронизация состояния между клиентами

### Ограничения

1. **Один демон на проект** — монолитная архитектура
2. **LevelDB** — не поддерживает распределённое хранение
3. **WebSocket** — ограничен одним экземпляром демона

### Возможности расширения

1. **Кластеризация** — разделение по локациям/проектам
2. **Распределённая БД** — миграция на Redis или подобные
3. **Message Queue** — использование Kafka/RabbitMQ для событий
4. **Микросервисы** — выделение отдельных сервисов для медиа, уведомлений и т.д.

## Разработка и расширение

### Добавление нового типа устройства

1. Добавить константу типа в `src/constants.js`:
   ```javascript
   module.exports.DEVICE_TYPE_NEW_DEVICE = 0xXX;
   ```

2. Реализовать обработку в `src/controllers/device.js`:
   ```javascript
   case DEVICE_TYPE_NEW_DEVICE: {
     // обработка событий
     break;
   }
   ```

3. Добавить команды управления в `src/controllers/service.js`

4. Обновить инициализацию в `src/actions/init.js` при необходимости

### Добавление нового драйвера

1. Создать директорию `src/drivers/new-driver/`
2. Реализовать интерфейс:
   ```javascript
   module.exports = {
     manage() { /* инициализация */ },
     handle(data) { /* обработка входящих */ },
     run(action) { /* выполнение команд */ }
   };
   ```
3. Зарегистрировать в `src/drivers/driver.js`
4. Добавить константу типа в `src/constants.js`

### Добавление новой WebSocket-команды

1. Добавить обработку в `src/websocket/handle.js`:
   ```javascript
   case 'NEW_COMMAND': {
     // логика
     break;
   }
   ```

2. Обновить документацию в README.md

## Отладка и диагностика

### Логирование

- Все ошибки выводятся в `console.error`
- Подробные логи можно добавить через `console.log` в ключевых местах

### Инструменты

1. **torch (MikroTik)** — мониторинг сетевого трафика:
   ```
   /tool torch ether1 port=3000
   ```

2. **netstat** — проверка открытых портов:
   ```
   netstat -an | grep 3000
   ```

3. **pm2** — управление процессом:
   ```
   pm2 monit
   pm2 logs
   ```

4. **LevelDB** — просмотр базы данных (требует утилит LevelDB)

### Типичные проблемы

1. **Таймауты WebSocket** — проверка доступности порта, firewall, маршрутизация
2. **Устройства не обнаруживаются** — проверка сети, multicast, портов
3. **Состояние не сохраняется** — проверка прав доступа к `var/db`
4. **Драйверы не запускаются** — проверка конфигурации проекта в LevelDB
