# Метаинформация скриптов

**Дата создания:** 2025-11-16  
**Версия:** 1.0

## Обзор

Документация описывает полную структуру метаинформации скриптов в системе ReactHome Daemon. Скрипты используются для автоматизации действий с устройствами и локациями.

## Структура скрипта

Скрипт представлен объектом JSON со следующими полями:

```json
{
  "type": "script",
  "site": "uuid-родительской-локации",
  "modified": 1763322695786,
  "timestamp": 1763322698986,
  "title": "Название скрипта",
  "code": "Код скрипта",
  "action": [
    "uuid-действия-1",
    "uuid-действия-2"
  ],
  "disabled": false
}
```

## Описание полей

### Обязательные поля

#### `type` (string, обязательное)
- **Тип:** `"script"`
- **Описание:** Идентификатор типа объекта. Для всех скриптов значение всегда `"script"`.
- **Пример:** `"script"`

#### `action` (array[string], обязательное)
- **Тип:** Массив UUID строк
- **Описание:** Список UUID действий, которые выполняются при запуске скрипта. Действия выполняются последовательно в порядке массива.
- **Формат:** `["uuid-действия-1", "uuid-действия-2", ...]`
- **Пример:** `["d21fb8e9-e1da-45b0-a9d2-0ab4cb775a6a"]`
- **Особенности:**
  - Если массив пустой, скрипт не выполняет действий
  - Каждое действие должно существовать в системе
  - Действия могут иметь задержку (`delay`)

### Опциональные поля

#### `site` (string, опциональное)
- **Тип:** UUID строки
- **Описание:** UUID родительской локации (Site), к которой привязан скрипт. Используется для организации скриптов по локациям.
- **Формат:** UUID v4
- **Пример:** `"a5b0a8f3-fe41-4235-b602-3a09e1eeddbb"`
- **Примечание:** Если поле отсутствует, скрипт считается глобальным

#### `title` (string, опциональное)
- **Тип:** Строка
- **Описание:** Человекочитаемое название скрипта. Используется для отображения в UI и поиска через WebSocket API.
- **Пример:** `"6.D.L.3 Toggle"`, `"start nlight лоджия"`, `"Start"`
- **Особенности:**
  - Может содержать любые символы, включая кириллицу
  - Используется для поиска скриптов через WebSocket API
  - Может отличаться от поля `code`

#### `code` (string, опциональное)
- **Тип:** Строка
- **Описание:** Код скрипта. Альтернативный идентификатор, используемый для поиска и идентификации скрипта. Может отличаться от `title`.
- **Пример:** `"Лоджия спот"`
- **Особенности:**
  - Может содержать любые символы, включая кириллицу
  - Не используется для поиска через WebSocket API (только через БД)
  - Может совпадать или отличаться от `title`
  - Полезно для скриптов, где `title` технический, а `code` - понятный пользователю

#### `timestamp` (number, опциональное)
- **Тип:** Unix timestamp в миллисекундах
- **Описание:** Время создания или последнего обновления скрипта в системе.
- **Формат:** Количество миллисекунд с 1 января 1970 года (Unix epoch)
- **Пример:** `1763322698986` (соответствует дате: 2025-11-16)
- **Примечание:** Автоматически устанавливается при создании/обновлении через `ACTION_SET`

#### `modified` (number, опциональное)
- **Тип:** Unix timestamp в миллисекундах
- **Описание:** Время последнего изменения скрипта пользователем или системой.
- **Формат:** Количество миллисекунд с 1 января 1970 года (Unix epoch)
- **Пример:** `1763322695786`
- **Примечание:** Может отличаться от `timestamp` при автоматических обновлениях

#### `disabled` (boolean, опциональное)
- **Тип:** Логическое значение
- **Описание:** Флаг отключения скрипта. Если `true`, скрипт не будет выполняться при вызове `ACTION_SCRIPT_RUN`.
- **Значения:**
  - `true` - скрипт отключен, выполнение блокируется
  - `false` или отсутствует - скрипт активен
- **Пример:** `false`
- **Поведение:** В `src/controllers/service.js:3162` проверяется перед выполнением:
  ```javascript
  if (script.disabled) return;
  ```

## Структура действия (Action)

Каждое действие в массиве `action` также является объектом в системе. Действие имеет следующую структуру:

```json
{
  "type": "ACTION_ON",
  "payload": {
    "id": "uuid-устройства"
  },
  "delay": 0
}
```

### Поля действия

#### `type` (string, обязательное)
- **Тип:** Константа действия
- **Описание:** Тип действия, которое должно быть выполнено.
- **Примеры:**
  - `"ACTION_ON"` - включить устройство
  - `"ACTION_OFF"` - выключить устройство
  - `"ACTION_TOGGLE"` - переключить состояние
  - `"ACTION_DIM"` - установить яркость
  - `"ACTION_SCRIPT_RUN"` - выполнить другой скрипт
  - И другие типы действий из `src/constants.js`

#### `payload` (object, обязательное)
- **Тип:** Объект с параметрами действия
- **Описание:** Параметры действия, зависящие от типа действия.
- **Примеры:**
  - Для `ACTION_ON`: `{"id": "uuid-устройства"}`
  - Для `ACTION_DIM`: `{"id": "uuid-устройства", "value": 50}`
  - Для `ACTION_SCRIPT_RUN`: `{"id": "uuid-скрипта"}`

#### `delay` (number, опциональное)
- **Тип:** Число (миллисекунды)
- **Описание:** Задержка перед выполнением действия. Если `delay > 0`, действие выполняется через указанное время после предыдущего.
- **Значения:**
  - `0` или отсутствует - выполняется немедленно
  - `> 0` - задержка в миллисекундах
- **Пример:** `1000` (задержка 1 секунда)
- **Поведение:** В `src/controllers/service.js:3166-3169`:
  ```javascript
  if (delay > 0) {
    setTimeout(run, delay, a);
  } else {
    run(a);
  }
  ```

## Выполнение скрипта

### Команда выполнения

```json
{
  "type": "ACTION_SCRIPT_RUN",
  "id": "uuid-скрипта"
}
```

### Процесс выполнения

1. **Получение скрипта:** `const script = get(id)` - получение скрипта из state по UUID
2. **Проверка отключения:** `if (script.disabled) return` - если скрипт отключен, выполнение прерывается
3. **Проверка действий:** `if (script && Array.isArray(script.action))` - проверка наличия действий
4. **Итерация по действиям:** Для каждого UUID в `script.action`:
   - Получение действия: `const { type, payload, delay } = get(i)`
   - Формирование команды: `const a = { action: i, type, ...payload }`
   - Выполнение:
     - Если `delay > 0`: `setTimeout(run, delay, a)`
     - Иначе: `run(a)`

**Код:** `src/controllers/service.js:3158-3173`

## Поиск и идентификация скриптов

### По UUID
- **Способ:** Прямое обращение по UUID
- **Команда:** `{"type": "get", "state": ["uuid-скрипта"]}`
- **Скорость:** Мгновенно
- **Надёжность:** ✅ 100%

### По title
- **Способ:** Поиск через WebSocket API (LIST + GET)
- **Команда:** 
  1. `{"type": "list"}` - получить все объекты
  2. `{"type": "get", "state": [...]}` - получить данные
  3. Фильтрация по `payload.title`
- **Скорость:** Медленно (обрабатывает все объекты)
- **Надёжность:** ✅ Работает

### По code
- **Способ:** Поиск через WebSocket API (LIST + GET) или БД
- **Команда:** Аналогично поиску по title, но фильтрация по `payload.code`
- **Скорость:** Медленно (обрабатывает все объекты)
- **Надёжность:** ✅ Работает (но поле `code` может отсутствовать)

**См. подробности:** [SCRIPT_SEARCH_METHODOLOGY.md](./SCRIPT_SEARCH_METHODOLOGY.md)

## Взаимосвязи

### Связь с локациями (Site)
- Скрипт может быть привязан к локации через поле `site`
- Локация может содержать массив скриптов в поле `script`
- Скрипты локации доступны через иерархию локаций

### Связь с действиями (Action)
- Скрипт содержит массив UUID действий в поле `action`
- Действия выполняются последовательно
- Действия могут иметь задержку (`delay`)

### Связь с проектом (Project)
- Скрипты могут быть частью проекта
- Проект может содержать скрипты в поле `script`
- Скрипты проекта доступны глобально

## Технические детали

### Хранение
- **Формат:** LevelDB
- **Ключ:** UUID скрипта
- **Значение:** JSON объект скрипта
- **Синхронизация:** Автоматическая при изменении через `ACTION_SET`

### Обновление
- **Команда:** `{"type": "ACTION_SET", "id": "uuid-скрипта", "payload": {...}}`
- **Автоматические поля:** `timestamp` устанавливается автоматически
- **Трансляция:** Изменения транслируются всем подключённым клиентам через `broadcast`

### Валидация
- **type:** Должен быть `"script"`
- **action:** Должен быть массивом UUID строк
- **UUID:** Должны быть валидными UUID v4

## Ограничения

1. **Максимальное количество действий:** Не ограничено явно, но рекомендуется не более 100 действий для производительности
2. **Задержка между действиями:** Максимальная задержка ограничена типом `number` в JavaScript (2^53 - 1 миллисекунд ≈ 285 лет)
3. **Вложенность скриптов:** Скрипты могут вызывать другие скрипты через `ACTION_SCRIPT_RUN`, но рекомендуется избегать циклических зависимостей

## Рекомендации

1. **Использование UUID:** Всегда используйте UUID для идентификации скриптов в коде
2. **Заполнение полей:** Заполняйте `title` и `code` для удобства поиска и отладки
3. **Документирование:** Документируйте сложные скрипты с множеством действий
4. **Тестирование:** Тестируйте скрипты перед использованием в продакшене
5. **Отключение:** Используйте `disabled: true` для временного отключения скриптов вместо удаления
