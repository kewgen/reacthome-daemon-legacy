# Методика поиска скриптов по названию

**Дата создания:** 2025-11-16  
**Версия:** 1.0

## Обзор

Данный документ описывает методику поиска скриптов в системе ReactHome по их названию (title) для получения UUID, необходимого для выполнения скриптов через WebSocket API.

## Проблема

Скрипты в системе идентифицируются по UUID, а не по человекочитаемым названиям. Для выполнения скрипта необходимо знать его UUID, но пользователи обычно знают только название скрипта.

## Методика поиска

### Способ 1: Поиск через WebSocket API (рекомендуется)

#### Шаг 1: Получение списка всех объектов

Отправьте команду `LIST` через WebSocket:

```json
{"type": "list"}
```

**Ответ:** Список всех объектов в формате:
```json
{
  "type": "list",
  "state": [
    ["uuid1", timestamp1],
    ["uuid2", timestamp2],
    ...
  ]
}
```

#### Шаг 2: Запрос данных скриптов

Отправьте команду `GET` для получения данных всех скриптов:

```json
{"type": "get", "state": ["uuid1", "uuid2", ...]}
```

**Ответ:** Серия сообщений `ACTION_SET` с данными объектов, включая скрипты:
```json
{
  "type": "ACTION_SET",
  "id": "script-uuid",
  "payload": {
    "type": "script",
    "title": "Название скрипта",
    "disabled": false,
    "action": ["action-uuid-1", "action-uuid-2"]
  }
}
```

#### Шаг 3: Фильтрация и поиск

1. Отфильтруйте сообщения с `payload.type === "script"`
2. Извлеките поле `payload.title`
3. Выполните поиск по названию (точное совпадение или частичное)

### Способ 2: Использование готовых скриптов

#### Скрипт простого поиска

```bash
node scripts/find-script-by-name.js "название скрипта"
```

**Пример:**
```bash
node scripts/find-script-by-name.js "Лоджия спот"
```

#### Скрипт расширенного поиска (с оценкой схожести)

```bash
node scripts/find-script-advanced.js "название скрипта"
```

**Пример:**
```bash
node scripts/find-script-advanced.js "Лоджия спот"
```

**Особенности:**
- Вычисляет схожесть названий (0-100%)
- Сортирует результаты по убыванию схожести
- Показывает топ-10 наиболее похожих скриптов
- Выделяет точные совпадения (100%)

### Способ 3: Поиск через Python тесты

Используйте функцию `_find_script_by_title` из тестов:

```python
from tests.integration.test_script_execution import _find_script_by_title
import websockets

async def find_script(title: str):
    async with websockets.connect("ws://192.168.88.4:3000") as ws:
        script_id = await _find_script_by_title(ws, title, timeout=3.0)
        return script_id
```

## Алгоритм оценки схожести

Расширенный поиск использует следующий алгоритм:

1. **Точное совпадение (100%)**: Названия полностью совпадают (после нормализации)
2. **Вхождение (80%)**: Одно название содержит другое
3. **Все слова совпадают (70%)**: Все слова из одного названия есть в другом
4. **Частичное совпадение (0-60%)**: Процент общих слов от общего количества слов

**Нормализация:**
- Приведение к нижнему регистру
- Удаление лишних пробелов
- Замена множественных пробелов одним

## Поиск в базе данных (продвинутый метод)

Если скрипт не найден через WebSocket API (например, скрипт новый и ещё не синхронизирован), можно попробовать поиск напрямую в базе данных LevelDB.

### Способ 1: Автоматический поиск через скрипт

Используйте готовый скрипт для поиска в БД:

```bash
# Поиск через SSH (если БД на удалённом сервере)
REACTHOME_USE_SSH=true \
REACTHOME_SSH_HOST="pi@192.168.88.4" \
node scripts/search-script-in-db.js "название скрипта"

# Поиск в локальной БД (если БД доступна локально)
REACTHOME_DB_PATH="/path/to/db" \
node scripts/search-script-in-db.js "название скрипта"
```

**Пример:**
```bash
REACTHOME_USE_SSH=true \
node scripts/search-script-in-db.js "Лоджия спот"
```

**Особенности:**
- Автоматически находит все файлы `.ldb` в указанной директории
- Использует утилиту `strings` для поиска текста в бинарных файлах
- Показывает результаты по каждому файлу БД
- Работает как через SSH, так и локально

### Способ 2: Ручной поиск через SSH

Если есть прямой доступ к серверу:

```bash
# Подключение к серверу
ssh pi@192.168.88.4

# Поиск файлов БД
cd /home/pi/reacthome-daemon
find var/db -name '*.ldb' -type f

# Поиск текста в файлах БД (используя strings)
find var/db -name '*.ldb' -exec sh -c 'strings "$1" | grep -i "название"' _ {} \;

# Или поиск в конкретном файле
strings var/db/179620.ldb | grep -i "название"

# Просмотр содержимого через ldb (если установлен)
ldb --db=var/db/179620.ldb dump | grep -i "название"
```

**Внимание:** 
- Этот метод требует доступа к серверу
- Утилита `strings` должна быть установлена на сервере
- Утилита `ldb` (LevelDB CLI) может быть не установлена

### Когда использовать поиск в БД

1. **Скрипт новый** - ещё не синхронизирован с WebSocket API
2. **Скрипт не найден через WebSocket** - возможно, проблема с синхронизацией
3. **Нужно найти UUID напрямую** - для отладки или восстановления
4. **Проверка существования скрипта** - если WebSocket API не отвечает

### Структура БД

База данных LevelDB хранит данные в бинарном формате:
- Ключи: UUID объектов (скриптов, устройств, локаций)
- Значения: JSON-объекты с данными (payload)
- Файлы: `.ldb` файлы в директории `var/db`

**Важно:** Поиск через `strings` может найти текст в любом месте файла, включая UUID и другие данные. Для точного поиска используйте WebSocket API или утилиту `ldb`.

## Рекомендации

1. **Используйте расширенный поиск** для нечётких запросов
2. **Проверяйте похожие скрипты**, если точное совпадение не найдено
3. **Сохраняйте UUID** найденных скриптов для последующего использования
4. **Используйте переменные окружения** для передачи UUID в тесты

## Ограничения

1. Поиск работает только для скриптов с заполненным полем `title`
2. Скрипты без названия не могут быть найдены по названию
3. Поиск чувствителен к регистру и пробелам (но нормализуется в расширенном поиске)
4. Большое количество скриптов (>1000) может замедлить поиск


**См. подробную документацию:** [LODGIA_SPOT_SCRIPT.md](./LODGIA_SPOT_SCRIPT.md)

### История поиска

**Проблема:** Скрипт не был найден через WebSocket API при поиске по названию "Лоджия спот".

**Причина:** 
- В системе скрипт хранится с названием "6.D.L.3 Toggle" в поле `title`
- Код "Лоджия спот" хранится в поле `code`, которое не используется при поиске через WebSocket API
- Поиск через WebSocket API ищет только по полю `title`, а не по `code`

**Решение:** Скрипт был найден через прямой поиск в базе данных LevelDB, где хранится полная информация, включая поле `code`.

**Наиболее похожие скрипты (через WebSocket API):**
1. "работа лоджия" (UUID: `41f41ead-2329-4a9e-a455-81da3651c6b4`) - схожесть: 30%
2. "nlight toggle лоджия" (UUID: `1066abce-435a-4dc3-a3b4-c3f68431c05f`) - схожесть: 20%
3. "start nlight лоджия" (UUID: `8a9daed5-e27a-43f1-b73a-852e99dee291`) - схожесть: 20%

### Выводы

1. **Поле `code` может отличаться от поля `title`** - при поиске учитывайте оба варианта
2. **Для новых скриптов** используйте поиск в БД, если WebSocket API не находит
3. **UUID скрипта** - наиболее надёжный способ идентификации
4. **Поиск в БД** позволяет найти скрипты по полю `code`, которое не индексируется в WebSocket API

### Рекомендации

1. **Используйте UUID** для надёжной идентификации скрипта
2. **Сохраняйте UUID** найденных скриптов для быстрого доступа
3. **При поиске** учитывайте, что название может отличаться от кода
4. **Для новых скриптов** используйте поиск в БД через `scripts/search-script-in-db.js`
