# Руководство по командам ACTION_SHELL_START и ACTION_SHELL_STOP

## Обзор

Команды `ACTION_SHELL_START` и `ACTION_SHELL_STOP` позволяют запускать и останавливать shell-команды на сервере демона через WebSocket.

**Зачем:** Управление внешними процессами, запуск скриптов, управление сервисами через единый интерфейс WebSocket.

## ACTION_SHELL_START

### Описание

Запускает shell-команду в отдельном процессе. Если процесс с указанным `id` уже запущен, сначала останавливает его.

### Формат команды

```json
{
  "type": "ACTION_SHELL_START",
  "id": "уникальный-id-процесса",
  "command": "shell-команда для выполнения"
}
```

### Параметры

- **`type`** (обязательно): `"ACTION_SHELL_START"`
- **`id`** (обязательно): Уникальный идентификатор процесса (строка). Используется для отслеживания и остановки процесса.
- **`command`** (опционально при прямом запуске shell): Shell-команда для выполнения (строка). Если не указана — берётся из shell-объекта (`get(id).command`). Выполняется через `child_process.spawn()` с опциями `{ detached: true, shell: true }`.

### Поведение

1. **Проверка существующего процесса:** Если процесс с указанным `id` уже запущен (есть `pid`), сначала останавливает его через `process.kill(-pid)`.
2. **Перехват media: URI (INC-015, INC-016):** Если команда начинается с `media:`, она перехватывается функцией `tryMediaCommand()` и выполняется через HTTP API (`http://192.168.88.5:3001`) без создания SSH-сессии. Это единственный поддерживаемый формат управления медиасервером.
3. **Запуск процесса:** Для остальных команд создаёт дочерний процесс через `childProcess.spawn(command, { detached: true, shell: true })`.
3. **Сохранение состояния:** При успешном запуске (`spawn` событие) сохраняет в state:
   ```json
   {
     "id": "уникальный-id-процесса",
     "command": "shell-команда",
     "value": true,
     "pid": 12345,
     "error": "",
     "stdout": "",
     "stderr": ""
   }
   ```
4. **Обработка ошибок:** При ошибке запуска сохраняет `error: "сообщение об ошибке"`.
5. **Обработка завершения:** При завершении процесса (`close` событие) обновляет state: `{ value: false, pid: null }`.

## ACTION_SHELL_STOP

### Описание

Останавливает запущенный процесс по его `id`. Используется для остановки shell-процессов, запущенных через `ACTION_SHELL_START`.

**Зачем:** Позволяет корректно завершить процессы, освобождая ресурсы и предотвращая "висящие" процессы.

### Формат команды

```json
{
  "type": "ACTION_SHELL_STOP",
  "id": "уникальный-id-процесса"
}
```

### Параметры

- **`type`** (обязательно): `"ACTION_SHELL_STOP"`
- **`id`** (обязательно): Идентификатор процесса, который нужно остановить (должен совпадать с `id`, использованным при `ACTION_SHELL_START`).

### Поведение

1. **Поиск процесса:** Получает `pid` из state по `id` через `get(id)`.
2. **Проверка наличия:** Если `pid` отсутствует или равен `null`, команда завершается без действий (`break`).
3. **Остановка процесса:** Вызывает `process.kill(-pid)` для остановки процесса и всех его дочерних процессов.
   - **Зачем:** Отрицательный PID (`-pid`) означает группу процессов, что позволяет остановить не только основной процесс, но и все его дочерние процессы, созданные через `detached: true`.
4. **Обработка ошибок:** Если `process.kill()` выбрасывает исключение (например, процесс уже завершён или не существует), обновляет state: `{ pid: null, value: false }`.
5. **Отсутствие обновления при успехе:** При успешной остановке команда не обновляет state явно - это происходит автоматически через обработчик `close` события в `ACTION_SHELL_START`.

### Код реализации

```javascript
case ACTION_SHELL_STOP: {
  const { id } = action;
  const { pid } = get(id) || {};
  if (pid) {
    try {
      process.kill(-pid);
    } catch (e) {
      set(id, { pid: null, value: false });
    }
  }
  break;
}
```

**Местоположение:** `src/controllers/service.js:3150-3161`

### Особенности реализации

1. **Безопасная остановка:** Используется `try-catch` для обработки случаев, когда процесс уже завершён или не существует.
2. **Группа процессов:** `process.kill(-pid)` останавливает всю группу процессов, что важно для процессов с `detached: true`.
   - **Зачем:** Отрицательный PID означает группу процессов (process group), что позволяет остановить не только основной процесс, но и все его дочерние процессы.
   - **Важно:** Это критично для процессов, запущенных с `detached: true`, которые могут создавать дочерние процессы.
3. **Нет явного обновления при успехе:** При успешной остановке state не обновляется явно в `ACTION_SHELL_STOP` - это делается через обработчик `close` в `ACTION_SHELL_START`:
   ```javascript
   child.on("close", () => {
     const { pid } = get(id) || {};
     if (pid === child.pid) {
       set(id, { value: false, pid: null })
     }
   });
   ```
   **Зачем:** Обработчик `close` гарантирует, что state обновится только для правильного процесса (проверка `pid === child.pid`).
4. **Обновление при ошибке:** Если `process.kill()` выбрасывает исключение, state обновляется явно: `{ pid: null, value: false }`.
   **Зачем:** Гарантирует, что state будет обновлён даже если процесс уже завершён или не существует.
5. **Идемпотентность:** Команда безопасна для повторного вызова - если `pid` отсутствует, команда просто завершается без действий (`break`).
6. **Минимальные параметры:** Команда требует только `id` - не нужны дополнительные параметры.

## Проверка состояния процесса

Для проверки состояния процесса запросите его данные через `GET`:

```json
{
  "type": "get",
  "state": ["уникальный-id-процесса"]
}
```

**Ответ:**
```json
{
  "type": "ACTION_SET",
  "id": "уникальный-id-процесса",
  "payload": {
    "command": "shell-команда",
    "value": true,
    "pid": 12345,
    "error": "",
    "stdout": "",
    "stderr": ""
  }
}
```

**Поля состояния:**
- **`value`**: `true` если процесс запущен, `false` если остановлен
- **`pid`**: PID процесса (число) или `null` если процесс не запущен
- **`command`**: Команда, которая была запущена
- **`error`**: Сообщение об ошибке (если была)
- **`stdout`**: Стандартный вывод (в текущей реализации не используется)
- **`stderr`**: Стандартный вывод ошибок (в текущей реализации не используется)

## Особенности и ограничения

### Особенности

1. **Автоматическая остановка при START:** При запуске нового процесса с тем же `id` через `ACTION_SHELL_START` старый процесс автоматически останавливается перед запуском нового:
   ```javascript
   const { pid } = get(id) || {};
   if (pid) {
     try {
       process.kill(-pid);  // Останавливает старый процесс
     } catch (e) {
       set(id, { pid: null, value: false });
     }
   }
   ```
   **Зачем:** Гарантирует, что только один процесс с данным `id` может быть запущен одновременно.

2. **Группа процессов:** Используется `process.kill(-pid)`, что останавливает процесс и все его дочерние процессы.
   - **Технические детали:** Отрицательный PID в Unix-системах означает process group ID (PGID).
   - **Важность:** Критично для процессов с `detached: true`, которые могут создавать дочерние процессы через shell или другие механизмы.

3. **Отсоединённый процесс:** Процесс запускается с опцией `detached: true`, что позволяет ему продолжать работу после завершения родительского процесса.
   - **Зачем:** Процесс не завершится при завершении демона Node.js.
   - **Последствие:** Требует явной остановки через `ACTION_SHELL_STOP` или `process.kill()`.

4. **Shell выполнение:** Команда выполняется через shell (`shell: true`), что позволяет использовать перенаправления, пайпы и другие shell-функции.
   - **Примеры:** `command1 | command2`, `command > file.txt`, `command && command2`

5. **Отсутствие обработки stdout/stderr:** В текущей реализации обработчики `stdout` и `stderr` закомментированы, поэтому вывод процессов не сохраняется в state.

### Рекомендации по кавычкам

При передаче command через JSON/WebSocket смешанные кавычки могут вызвать проблемы. Протокол `media:` URI специально спроектирован без кавычек — используйте его для управления аудио.

### Ограничения

1. **stdout/stderr:** В текущей реализации стандартный вывод и вывод ошибок не сохраняются (закомментированы обработчики `data` в `ACTION_SHELL_START`).
   - **Код:** `src/controllers/service.js:3124-3135` (закомментировано)
   - **Причина:** Вероятно, для предотвращения переполнения state большими объёмами вывода.

2. **Удалённые процессы:** `ACTION_SHELL_STOP` останавливает только процессы, запущенные на сервере демона (локально).
   - **Проблема:** Если процесс запущен через SSH на удалённом сервере, `process.kill(-pid)` остановит только локальный SSH-процесс, но не процесс на удалённом сервере.
   - **Решение:** Используйте `ACTION_SHELL_START` с командой остановки на удалённом сервере (например, `ssh ... pkill ...`).

3. **Отсутствие проверки существования процесса:** Команда не проверяет, действительно ли процесс с указанным `pid` ещё существует перед попыткой остановки.
   - **Последствие:** Может выбрасывать исключение, которое обрабатывается в `catch` блоке.
   - **Компенсация:** Ошибка обрабатывается корректно, state обновляется.

4. **Нет информации о причине остановки:** Команда не различает причины остановки (завершён нормально, убит, ошибка).
   - **Последствие:** Невозможно определить, был ли процесс остановлен принудительно или завершился сам.

5. **Одновременная остановка:** Если несколько процессов имеют одинаковый `pid` (что невозможно, но теоретически), остановится только один.

## Интеграция с проектами

### Автоматическая остановка при старте демона

При запуске демона (`daemon.js:start()`) все shell-процессы из проекта автоматически останавливаются:

```javascript
const { timer = [], schedule = [], shell = [] } = get(project) || {};
// ...
for (const id of shell) {
  service.run({ id, type: ACTION_SHELL_STOP });
}
```

**Зачем:** Обеспечивает чистый старт проекта без "висящих" процессов от предыдущих запусков. Это гарантирует, что при перезапуске демона все старые shell-процессы будут корректно завершены.

**Местоположение:** `daemon.js:68-70`

**Последовательность при старте:**
1. Останавливаются все shell-процессы из массива `project.shell[]`
2. Запускаются расписания (`schedule`)
3. Восстанавливаются таймеры (`timer`)
4. Выполняется стартовый скрипт (`onStart`)

### Структура проекта

Shell-процессы хранятся в проекте в массиве `shell[]`:

```json
{
  "id": "project-uuid",
  "type": "project",
  "shell": [
    "shell-process-id-1",
    "shell-process-id-2"
  ]
}
```

**Зачем:** Массив `shell[]` позволяет системе автоматически управлять всеми shell-процессами проекта при его запуске и остановке.
