# Архитектура THERMOSTAT: Программный элемент системы климата

**Дата:** 11 декабря 2025  
**Статус:** Документация

## 🎯 Главное

> **THERMOSTAT - это ПРОГРАММНЫЙ элемент системы климата, а НЕ физическое устройство.**

## 📚 Определение

**THERMOSTAT (термостат)** - программная логика управления температурой, которая:
- Считывает данные с датчиков температуры
- Принимает решения о включении/выключении обогрева/охлаждения
- Управляет актуаторами через скрипты
- Может быть связана с физическим интерфейсом (кнопки) через `bind`

## 📊 Типы элементов в системе

| Тип элемента | Природа | Примеры | Особенности |
|--------------|---------|---------|-------------|
| **Физические устройства** | Аппаратура | S4, S3, R3, R4, DIM | Реальное железо с MAC-адресами |
| **Датчики (sensors)** | Физические | TEMPERATURE_EXT, DOPPLER | Измеряют параметры среды |
| **Потребители (consumers)** | Логические | light_220, warm_floor, valve | Управляют актуаторами |
| **Термостаты (thermostats)** | Программные | thermostat | Логика управления климатом |
| **Скрипты (scripts)** | Программные | script | Последовательность действий |
| **Действия (actions)** | Программные | ACTION_ON, ACTION_OFF | Команды для устройств |

## 🔗 Связи термостата

### 1. sensor (обязательная связь)

**Назначение:** Источник данных о температуре

```json
{
  "type": "thermostat",
  "sensor": "28:aa:47:0b:70:21:07:c8"  // ID датчика температуры
}
```

**Что происходит:**
- Термостат периодически считывает `temperature` с датчика
- Сравнивает с `target_temp` (целевая температура)
- Принимает решение о включении/выключении

**Цепочка данных:**
```
1-Wire шина → Датчик (28:aa:...) → sensor → THERMOSTAT → Решение
```

### 2. bind (опциональная связь)

**Назначение:** Связь с физическим интерфейсом (кнопка)

```json
{
  "type": "thermostat",
  "bind": "80:98:67:45:dc:23/di/4"  // S4 Душ / DI/4
}
```

**Что происходит:**
- Нажатие кнопки DI/4 на S4 панели → переключает режим термостата
- Термостат может показывать индикацию на панели
- Можно использовать встроенную температуру S4 как резервный источник

**Цепочка управления:**
```
Кнопка DI/4 → bind → THERMOSTAT → Смена режима
```

### 3. onStartHeat / onStopHeat (обязательные связи)

**Назначение:** Скрипты управления обогревом

```json
{
  "type": "thermostat",
  "onStartHeat": "b3ebb927-5629-41d1-9b16-5f8f81db0f99",
  "onStopHeat": "22046a4c-2325-498e-a914-76c3cdcec900"
}
```

**Что происходит:**
- Термостат запускает скрипт `onStartHeat` при temp < target
- Скрипт содержит последовательность ACTION для актуаторов
- `onStopHeat` выключает обогрев при достижении target

**Цепочка управления:**
```
THERMOSTAT → onStartHeat → SCRIPT → ACTION_ON → WARM_FLOOR → RELAY
```

### 4. onStartCool / onStopCool (опциональные связи)

**Назначение:** Скрипты управления охлаждением

```json
{
  "type": "thermostat",
  "onStartCool": "...",
  "onStopCool": "..."
}
```

**Для систем с кондиционированием.**

## 💡 Почему термостат программный?

### Преимущества программной реализации

1. **Гибкость логики:**
   - Можно менять алгоритмы без изменения железа
   - Легко добавлять новые режимы (день/ночь, эконом)
   - Поддержка сложных сценариев (гистерезис, задержки)

2. **Универсальность:**
   - Один термостат может управлять несколькими актуаторами
   - Не привязан к конкретному оборудованию
   - Можно использовать разные типы датчиков

3. **Масштабируемость:**
   - Легко создать много термостатов
   - Централизованное управление всей системой климата
   - Единая логика для всех помещений

4. **Интеграция:**
   - Управление через WebSocket API
   - Интеграция с UI (веб-интерфейс, мобильное приложение)
   - Связь с другими системами (графики, логирование)

### Сравнение с физическим термостатом

| Аспект | Физический термостат | Программный термостат |
|--------|---------------------|---------------------|
| **Расположение** | На стене в помещении | В БД системы |
| **Датчик** | Встроенный | Любой в системе |
| **Управление** | Кнопки/экран | API + опционально кнопка через bind |
| **Логика** | Простая (вкл/выкл) | Сложная (скрипты, сценарии) |
| **Изменение** | Замена устройства | Обновление конфигурации |
| **Актуаторы** | 1-2 реле | Любое количество через скрипты |
| **Стоимость** | 50-200$ за устройство | ~0$ (программная логика) |

## 🔧 Пример конфигурации

### Минимальная конфигурация

```json
{
  "type": "thermostat",
  "title": "Термостат спальни",
  "site": "bedroom-uuid",
  
  // Обязательные поля
  "sensor": "28:xx:xx:xx:xx:xx:xx:xx",  // датчик температуры
  "onStartHeat": "script-uuid-1",       // скрипт включения обогрева
  "onStopHeat": "script-uuid-2",        // скрипт выключения обогрева
  
  // Параметры
  "target_temp": 22,                    // целевая температура
  "hysteresis": 0.5                     // гистерезис (опционально)
}
```

### Полная конфигурация

```json
{
  "type": "thermostat",
  "title": "Термостат ванной",
  "code": "Т Ванна",
  "site": "bathroom-uuid",
  
  // Входы
  "sensor": "28:a3:6a:79:51:21:01:07",     // датчик пола
  "bind": "50:35:cc:2d:8e:fe/di/4",        // кнопка на S4 Ванна
  
  // Скрипты обогрева
  "onStartHeat": "heat-start-uuid",
  "onStopHeat": "heat-stop-uuid",
  
  // Скрипты охлаждения (если есть)
  "onStartCool": "cool-start-uuid",
  "onStopCool": "cool-stop-uuid",
  
  // Параметры
  "target_temp": 28,
  "hysteresis": 1.0,
  "mode": "heat",                          // heat / cool / auto
  
  // Дополнительно
  "enabled": true,
  "schedule": {
    "weekday": { "start": "06:00", "temp": 28 },
    "weekend": { "start": "08:00", "temp": 26 }
  }
}
```

## 🎯 Типичные сценарии

### Сценарий 1: Тёплый пол

```
Термостат "Т Душ"
└─ sensor: Датчик "Пол душ" (26.81°C)
└─ target_temp: 28°C
└─ Решение: temp < target → включить обогрев
└─ onStartHeat → Script
    └─ ACTION_ON → Потребитель "ЭлПол"
        └─ bind: R3/do/10 → Реле
            └─ Физически: включается тёплый пол
```

### Сценарий 2: Управление с кнопки

```
Пользователь нажимает кнопку DI/4 на S4 панели
└─ bind: S4/di/4 → Термостат "Т Душ"
    └─ Переключение режима: auto → manual
    └─ onStopHeat → Script
        └─ ACTION_OFF → Потребитель "ЭлПол"
            └─ bind: R3/do/10 → Реле
                └─ Физически: выключается тёплый пол
```

### Сценарий 3: Несколько актуаторов

```
Термостат "Т Спальня"
└─ onStartHeat → Script
    ├─ ACTION_ON → Потребитель "Радиатор" → R4/do/1
    ├─ ACTION_SET(50%) → Потребитель "Вентилятор" → DIM/1
    └─ ACTION_ENABLE → Потребитель "Циркуляция" → R3/do/5
```
