# Алгоритм привязки термостатов к DI/4 и S4 модулям

## 🎯 Цель

Установить правильную архитектуру связи между термостатами, сенсорными модулями (S4) и датчиками температуры для обеспечения:
- Управления термостатом с физической кнопки на панели S4
- Корректного считывания температуры
- Индикации состояния на сенсорной панели

## 📝 Алгоритм привязки термостата (пошаговый)

### Шаг 1: Определить помещение

```bash
# Найти термостат
thermostat_id="555265f5-51ae-443c-84a1-223418fda929"
site_id=$(узнать site термостата)
# site_id="7669d319-f98f-41a0-a021-97c808442481" (Душ)
```

**Требование:** Термостат должен быть в том же помещении, что и S4 модуль.

### Шаг 2: Найти S4 модуль в помещении

```bash
# Найти S4 модуль в том же помещении
# Тип: 37 (0x25) - S4 модуль
# Или тип: 32 (0x20) - сенсорный модуль

# Для Душ: S4 Душ
s4_id="80:98:67:45:dc:23"
s4_type=37  # 0x25
```

**Требование:** У S4 модуля должен быть встроенный датчик температуры (`temperature` field).

### Шаг 3: Определить датчик температуры

**Вариант A: Использовать внешний 1-Wire датчик (рекомендуется)**

```json
// В S4 модуле:
{
  "temperature_ext": [
    "28:aa:47:0b:70:21:07:c8"  // ID внешнего датчика
  ]
}

// Датчик:
{
  "id": "28:aa:47:0b:70:21:07:c8",
  "type": 240,
  "title": "Пол душ",
  "master": "80:98:67:45:dc:23",  // ← Ссылка на S4
  "temperature": 26.81
}

// В термостате:
{
  "sensor": "28:aa:47:0b:70:21:07:c8"  // ID внешнего датчика
}
```

**Вариант B: Использовать встроенный датчик S4 (текущая реализация)**

```json
// В термостате:
{
  "sensor": "80:98:67:45:dc:23"  // ID самого S4 модуля
}
```

**Примечание:** В текущей системе используется вариант B (встроенный датчик S4).

### Шаг 4: Добавить bind к DI/4

```json
// В термостате:
{
  "type": "thermostat",
  "title": "Т Душ",
  "site": "7669d319-f98f-41a0-a021-97c808442481",
  "bind": "80:98:67:45:dc:23/di/4",  // ← ДОБАВИТЬ!
  "sensor": "80:98:67:45:dc:23",  // или ID внешнего датчика
  "onStartHeat": "b3ebb927-5629-41d1-9b16-5f8f81db0f99",
  "onStopHeat": "22046a4c-2325-498e-a914-76c3cdcec900"
}
```

**Формат bind:** `<S4_MODULE_ID>/di/<CHANNEL_NUMBER>`

**Почему DI/4?**
- Стандартный канал для термостатов в системе
- Позволяет управлять термостатом кнопкой на панели S4
- Обеспечивает индикацию состояния

### Шаг 5: Проверить скрипты управления

```json
{
  "onStartHeat": "UUID_скрипта",  // Включение обогрева
  "onStopHeat": "UUID_скрипта",   // Выключение обогрева
  "onStartCool": "UUID_скрипта",  // Включение охлаждения (опционально)
  "onStopCool": "UUID_скрипта"    // Выключение охлаждения (опционально)
}
```

Каждый скрипт должен содержать действия (`action` array) для управления исполнительными устройствами.

### Шаг 6: Проверить целостность конфигурации

**Чек-лист:**

- [ ] Термостат и S4 модуль в одном помещении (`site` совпадают)
- [ ] У термостата есть `bind` к DI/4 S4 модуля
- [ ] У термостата есть `sensor` (внешний датчик или сам S4)
- [ ] Если `sensor` - внешний датчик:
  - [ ] У датчика есть `master` = ID S4 модуля
  - [ ] Датчик включен в `temperature_ext` S4 модуля
- [ ] Все скрипты (`onStartHeat`, `onStopHeat` и т.д.) существуют
- [ ] Скрипты имеют действия (`action` array не пустой)

## 🎯 План исправления

### Приоритет 1: Добавить bind ко ВСЕМ термостатам

Обновить в базе данных для каждого термостата:

```sql
-- Пример для Т Душ
UPDATE thermostat 
SET bind = "80:98:67:45:dc:23/di/4"
WHERE id = "555265f5-51ae-443c-84a1-223418fda929"
```

### Приоритет 2: Исправить sensor для Т Душ

```sql
-- Т Душ должен использовать внешний датчик
UPDATE thermostat 
SET sensor = "28:aa:47:0b:70:21:07:c8"
WHERE id = "555265f5-51ae-443c-84a1-223418fda929"
```
