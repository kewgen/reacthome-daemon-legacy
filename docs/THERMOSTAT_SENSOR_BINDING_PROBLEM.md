# Проблема привязки термостатов и датчиков температуры

## 🎯 Что такое THERMOSTAT

**THERMOSTAT - это программный элемент системы климата.**

### Архитектура термостата

```
┌──────────────────────────────────────────────────────────┐
│ THERMOSTAT (программная логика управления климатом)     │
│                                                          │
│ • НЕ физическое устройство                              │
│ • Программный контроллер температуры                    │
│ • Управляет актуаторами (через scripts)                 │
│ • Считывает данные с датчиков (через sensor)            │
│ • Связан с DI каналом для управления (через bind)       │
└──────────────────────────────────────────────────────────┘
          ↓                    ↓                    ↓
    ┌─────────┐          ┌─────────┐          ┌─────────┐
    │ SENSOR  │          │  DI/4   │          │ SCRIPT  │
    │ (датчик)│          │ (канал) │          │ (логика)│
    └─────────┘          └─────────┘          └─────────┘
```

### Связи термостата

| Поле | Связь с | Назначение |
|------|---------|------------|
| `sensor` | ID датчика температуры | Считывание текущей температуры |
| `bind` | `DEVICE_ID/di/4` | Управление с физического интерфейса (кнопки) |
| `onStartHeat` | ID script | Скрипт запуска обогрева |
| `onStopHeat` | ID script | Скрипт остановки обогрева |
| `onStartCool` | ID script | Скрипт запуска охлаждения |
| `onStopCool` | ID script | Скрипт остановки охлаждения |

## 🔍 Обнаруженная проблема

При анализе термостата "Т Душ" обнаружены следующие архитектурные проблемы:

### ⚡ Важная архитектурная особенность: DI/4 как 1-Wire шина

**Датчики температуры физически подключены к DI/4!**

В S4 модулях **DI/4 канал используется для 1-Wire шины**:
- Физически: датчики температуры подключены к DI/4
- Программно: связь через `master` и `temperature_ext[]`
- Термостаты должны быть привязаны к тому же DI/4

```
S4 Душ (80:98:67:45:dc:23)
├─ DI/4 (физически) ← 1-Wire шина
│  └─ Датчики температуры подключены сюда
│
├─ temperature_ext[] (программно)
│  └─ [0] 28:aa:47:0b:70:21:07:c8 (Пол душ)
│
└─ bind к DI/4 (программно)
   └─ Термостат "Т Душ" должен быть здесь
```

### 1. Термостат не имеет привязки к DI каналу

**Термостат:** Т Душ (`555265f5-51ae-443c-84a1-223418fda929`)
- **Тип:** `thermostat` (программный элемент системы климата)
- **Помещение:** Душ
- **Проблема:** Отсутствует поле `bind`
- **Ожидается:** `bind: "80:98:67:45:dc:23/di/4"` (S4 Душ / DI/4)

**Последствия:**
- Невозможно управлять термостатом с физической кнопки на S4 панели
- Нет связи программного термостата с физическим интерфейсом (DI канал)
- Отсутствует возможность ручного управления через DI/4
- Термостат работает только программно (без физического управления)

### 2. "Потерянный" датчик температуры

**Датчик:** `28:aa:50:07:c5:03:c0:2c`
- **master:** `80:98:67:45:dc:23` (S4 Душ)
- **Температура:** 66.66°C (аномально высокая!)
- **Проблема:** НЕ включен в массив `temperature_ext` мастер-устройства
- **Статус:** offline, not ready

**S4 Душ** имеет:
```json
{
  "temperature_ext": [
    "28:aa:47:0b:70:21:07:c8"  // Только 1 датчик
  ]
}
```

Но **2 датчика** имеют `master = "80:98:67:45:dc:23"`:
1. ✅ `28:aa:47:0b:70:21:07:c8` - "Пол душ" (26.81°C) - в `temperature_ext`
2. ⚠️ `28:aa:50:07:c5:03:c0:2c` - без названия (66.66°C) - **НЕ** в `temperature_ext`

## 💡 Возможные причины "потерянного" датчика

### Вариант 1: Неисправный датчик
- Температура **66.66°C** аномально высокая для жилого помещения
- Датчик может быть **физически неисправен**
- Был удален из `temperature_ext` из-за постоянных ошибок чтения
- Статус: `online: false, ready: false`

### Вариант 2: Датчик привязан к DI/4 (нестандартная архитектура)
- Датчик подключен не через 1-Wire, а через **DI канал**
- Термостат должен иметь `bind: "80:98:67:45:dc:23/di/4"` для чтения
- Это объясняет отсутствие в `temperature_ext` (читается через DI, а не 1-Wire)

### Вариант 3: Ошибка конфигурации
- Датчик рабочий, но **забыли** добавить в `temperature_ext`
- Требуется обновление конфигурации S4 Душ

## ✅ Рекомендуемое решение

### Шаг 1: Добавить bind к программному термостату

**Что делает bind для программного термостата:**
- Связывает программную логику термостата с физической кнопкой DI/4
- Позволяет управлять термостатом через сенсорную панель S4
- Дает доступ к встроенному датчику температуры S4 (резервный источник)

```json
{
  "type": "thermostat",  // ← программный элемент системы климата
  "title": "Т Душ",
  "bind": "80:98:67:45:dc:23/di/4",  // ← ДОБАВИТЬ (связь с физ. кнопкой)
  "sensor": "28:aa:47:0b:70:21:07:c8",  // датчик температуры
  "onStartHeat": "b3ebb927-5629-41d1-9b16-5f8f81db0f99",  // скрипт вкл
  "onStopHeat": "22046a4c-2325-498e-a914-76c3cdcec900",  // скрипт выкл
  ...
}
```

**Преимущества bind для программного термостата:**
- ✅ Физическое управление программным термостатом с кнопки DI/4 на S4
- ✅ Связь программной логики с физическим интерфейсом
- ✅ Возможность использовать встроенную температуру S4 (25.64°C) как резервный источник
- ✅ Индикация состояния термостата на сенсорной панели S4
- ✅ Ручное переключение режимов (нагрев/охлаждение) через кнопку
