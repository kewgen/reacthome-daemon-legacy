# Стандарт формата цепочек трассировки (Trace Report Format)

Этот документ фиксирует утвержденный формат вывода цепочек событий для отчетов, логов и инструментов анализа.

## Структура цепочки

Каждая цепочка выводится как отдельный блок:

```markdown
<trace_id> [⚠️ >10 шагов]
<ISO_TIMESTAMP>

> <Элемент_1> (0ms) → <Элемент_2> (<offset_ms>) → <Элемент_N> (<offset_ms>)
```

### Правила формирования (стандарт)

1.  **Заголовок**:
    - Содержит полный UUID `trace_id`.
    - Если в цепочке больше 10 шагов, добавляется предупреждение `[⚠️ >10 шагов]`.
    - Если цепочка не полная, добавляется предупреждение `[⚠️ не полная]`.
2.  **TimeStart**: 
    - Точное ISO-время первого события в цепочке (обычно это SOURCE или SCRIPT executed).
3.  **Одна строка**: 
    - Вся причинно-следственная связь выводится в одну строку, начинающуюся с символа цитирования `> `.
    - Элементы разделяются стрелкой ` → `.
4.  **Состав элемента**:
    - Формат: `Human_Name / action_type (offset_ms)`.
    - `Human_Name`: Понятное имя устройства или скрипта (из `device.human`).
    - `action_type`: Тип действия (`press`, `click`, `script`, `consumer`, `actuator`, `humidity` и т.д.).
5.  **Интервал в скобках (Offset)**:
    - Это **смещение в миллисекундах от начала цепочки** (`TimeStart`).
    - У первого элемента всегда `(0ms)`.
    - Последовательность элементов определяется строго временем срабатывания (`timestamp`).
6.  **Полнота**: 
    - Цепочка считается полной, если она отображает путь от источника до потребителя: `SOURCE → [SCRIPT] → [ACTUATOR] → CONSUMER`.
7.  **Текст без оформления**: 
    - Внутри строки последовательности (в именах и типах действий) запрещено использовать символы markdown-разметки (`*`, `_`, `**`), чтобы не затруднять копирование и машинный парсинг.

## Пример

357fca28-2d74-4b0e-9c8c-2acc315e496d
2025-12-24T19:08:26.238Z

> S4 Душ / press(0ms) → Свет/2.D.LED.6 Душ / consumer(1056ms) → 2.D.LED.6 toggle / script(1058ms) → light on душ / script(1059ms) → D7 / dim/1 / actuator (1060ms)
