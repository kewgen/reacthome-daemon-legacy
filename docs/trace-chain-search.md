# Поиск цепочки событий по trace_id

## Запрос в OpenSearch Dashboards

### 1. Найти все события с trace_id

```
trace_id: "38cd6684-7789-46c9-8620-40fc0850b696"
```

### 2. Или через Query DSL:

```json
{
  "query": {
    "term": {
      "trace_id.keyword": "38cd6684-7789-46c9-8620-40fc0850b696"
    }
  },
  "sort": [
    { "timestamp": { "order": "asc" } }
  ],
  "size": 100
}
```

## Анализ цепочки

### Известные участники:

1. **Скрипт-инициатор:**
   - ID: `54083237-45d5-47c8-8560-f91a2b205a80`
   - Human: "start cool старшая"
   - Роль: Запускает цепочку

2. **Целевой скрипт:**
   - ID: `4a86f6b1-a621-4617-9f1f-e6ad2f471587`
   - Human: "🔵/Сплит on старшая"
   - Роль: Выполняется по команде от инициатора

3. **trace_id:** `38cd6684-7789-46c9-8620-40fc0850b696`
   - Объединяет все связанные события

## Что искать в результатах:

1. **Начало цепочки:**
   - Событие без trigger.ref (или trigger.ref = null)
   - Самый ранний timestamp
   - Это корневое событие

2. **Промежуточные события:**
   - trigger.ref указывает на предыдущее событие
   - Могут быть разные device.type

3. **Конечные события:**
   - Последние по timestamp
   - Результаты выполнения

## Пример структуры цепочки:

```
[Пользователь/Таймер]
    ↓ (запускает)
[Скрипт "start cool старшая"]
    ↓ (trigger.ref)
[Скрипт "🔵/Сплит on старшая"]
    ↓ (возможно)
[Устройства: кондиционер, свет, и т.д.]
```

## Локальный монитор

Монитор запущен и ловит события скриптов в реальном времени:
- Файл: `logs/device-monitor/scripts-trace-2025-12-08.log`
- Фильтр: type = script
- Показывает: trace_id, trigger, ID

Когда произойдут новые события с этим trace_id, они появятся в логе.
