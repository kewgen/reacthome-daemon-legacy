## Реализованные скрипты

### 1. `scripts/system/emergency-restore-server.sh`

Основной скрипт для экстренного восстановления. Выполняет все шаги плана автоматически.

**Использование:**
```bash
export REACTHOME_PI_PASS='ваш_пароль'
./scripts/system/emergency-restore-server.sh [путь_к_бэкапу]
```

**Пример:**
```bash
./scripts/system/emergency-restore-server.sh /tmp/db-backup-20251206_231611.tar.gz
```

**Что делает:**
1. Проверяет наличие и целостность бэкапа
2. Останавливает демон
3. Создаёт бэкапы текущего состояния (БД, логи)
4. Удаляет все логи
5. Очищает БД
6. Восстанавливает БД из бэкапа
7. Приводит код к состоянию `main` (git reset --hard origin/main)
8. Запускает демон
9. Анализирует логи и проверяет успешность восстановления

### 2. `scripts/system/emergency-rollback.sh`

Скрипт для отката при неудачном восстановлении.

**Использование:**
```bash
export REACTHOME_PI_PASS='ваш_пароль'
./scripts/system/emergency-rollback.sh [путь_к_директории_с_бэкапами]
```

**Пример:**
```bash
./scripts/system/emergency-rollback.sh ./backups/emergency-restore-20250128_120000
```

**Что делает:**
1. Останавливает демон
2. Восстанавливает БД из бэкапа, созданного перед восстановлением
3. Запускает демон
4. Проверяет успешность отката

## Пошаговый процесс восстановления

### Шаг 0: Подготовка (выполняется автоматически)

1. **Проверка наличия бэкапа**
   - Локально или на малинке
   - Копирование на малинку, если нужно

2. **Проверка целостности архива**
   - Валидация tar.gz
   - Проверка структуры архива

3. **Создание директории для бэкапов**
   - `./backups/emergency-restore-YYYYMMDD_HHMMSS/`

### Шаг 1: Остановка демона

```bash
pm2 stop daemon
sleep 2
pm2 list | grep daemon  # Проверка остановки
```

### Шаг 2: Создание бэкапа текущего состояния

**Бэкап БД:**
```bash
tar -czf /tmp/db-current-YYYYMMDD_HHMMSS.tar.gz -C /home/pi/reacthome-daemon var/db
```

**Бэкап логов:**
```bash
tar -czf /tmp/logs-current-YYYYMMDD_HHMMSS.tar.gz ~/.pm2/logs ~/.pm2/pm2.log
```

**Бэкап event логов (если есть):**
```bash
tar -czf /tmp/event-logs-current-YYYYMMDD_HHMMSS.tar.gz -C /home/pi/reacthome-daemon var/log
```

Все бэкапы копируются локально в `./backups/emergency-restore-*/`

### Шаг 3: Удаление всех логов

```bash
# Логи PM2
rm -f ~/.pm2/logs/daemon-*.log ~/.pm2/pm2.log

# Event логи
rm -f /home/pi/reacthome-daemon/var/log/events-*.jsonl

# Логи LevelDB
rm -f /home/pi/reacthome-daemon/var/db/LOG
```

### Шаг 4: Очистка БД

```bash
rm -rf /home/pi/reacthome-daemon/var/db/*
```

### Шаг 5: Восстановление БД из бэкапа

**⚠️ ВАЖНО:** Скрипт автоматически использует надёжный метод распаковки через временную директорию.

**Автоматический метод (используется в скрипте):**
```bash
# 1. Создание временной директории
TMP_DIR="/tmp/db-restore-tmp-$$"
mkdir -p $TMP_DIR

# 2. Распаковка во временную директорию
cd $TMP_DIR
tar -xzf /tmp/db-backup-20251206_231611.tar.gz

# 3. Проверка содержимого
ls -la var/db/  # Должны быть файлы БД

# 4. Копирование в целевую директорию
cd /home/pi/reacthome-daemon
rm -rf var/db/*
cp -r $TMP_DIR/var/db/* var/db/

# 5. Установка прав
chown -R pi:pi var/db

# 6. Очистка временной директории
rm -rf $TMP_DIR
```

**Проверка восстановления (выполняется автоматически):**
```bash
# Проверка файлов
ls -lh var/db  # Должны быть: *.ldb, *.log, MANIFEST-*, CURRENT, LOCK

# Проверка ключевых файлов
test -f var/db/CURRENT && echo "✅ CURRENT найден" || echo "❌ CURRENT отсутствует"
ls -1 var/db/MANIFEST-* | wc -l  # Должно быть > 0
ls -1 var/db/*.ldb | wc -l  # Должно быть > 0

# Подсчёт записей в БД
node -e "const {Level}=require('level');(async()=>{try{const db=new Level('var/db',{valueEncoding:'json'});let c=0;for await(const _ of db.iterator())c++;await db.close();console.log('Записей в БД:',c);}catch(e){console.error('ERROR:',e.message);process.exit(1);}})();"
```

**Ожидаемый результат:**
- Файлов в БД: 8-15 (зависит от размера БД)
- Размер БД: обычно 3-10 MB
- Записей в БД: обычно 1000-3000 (зависит от конфигурации)

### Шаг 6: Приведение кода к начальному состоянию

```bash
cd /home/pi/reacthome-daemon
git fetch origin
git reset --hard origin/main
git clean -fd
```

### Шаг 7: Запуск демона

```bash
pm2 start daemon.js --name daemon
sleep 5
pm2 list | grep daemon
```

### Шаг 8: Анализ логов

**Проверка статуса:**
```bash
pm2 list | grep daemon
```

**Проверка логов:**
```bash
pm2 logs daemon --lines 50
```

**Поиск сообщений о загрузке БД:**
```bash
pm2 logs daemon --lines 100 | grep -E "(Загружено записей|state.init|LevelDB)"
```

**Поиск ошибок:**
```bash
pm2 logs daemon --lines 200 | grep -iE "(error|Error|ERROR|exception|Exception|fatal|Fatal|FATAL)"
```

**Проверка количества записей в БД:**
```bash
node -e "const {Level}=require('level');(async()=>{try{const db=new Level('var/db',{valueEncoding:'json'});let c=0;for await(const _ of db.iterator())c++;await db.close();console.log(c);}catch(e){console.error('ERROR:',e.message);process.exit(1);}})();"
```

## План отката

Если восстановление не удалось, выполните откат:

### Автоматический откат

```bash
export REACTHOME_PI_PASS='ваш_пароль'
./scripts/system/emergency-rollback.sh ./backups/emergency-restore-YYYYMMDD_HHMMSS
```

### Ручной откат

1. **Остановить демон:**
   ```bash
   pm2 stop daemon
   ```

2. **Восстановить БД:**
   ```bash
   cd /home/pi/reacthome-daemon
   rm -rf var/db/*
   tar -xzf /tmp/db-current-YYYYMMDD_HHMMSS.tar.gz -C var
   chown -R pi:pi var/db
   ```

3. **Вернуть код (если нужно):**
   ```bash
   cd /home/pi/reacthome-daemon
   git reset --hard HEAD@{1}
   # или
   git reset --hard <commit_hash>
   ```

4. **Запустить демон:**
   ```bash
   pm2 start daemon
   ```

5. **Проверить логи:**
   ```bash
   pm2 logs daemon --lines 100
   ```

## Критические моменты

### 1. Проверка целостности бэкапа

Перед восстановлением обязательно проверьте:
```bash
tar -tzf db-backup-20251206_231611.tar.gz | head -20
```

Должна быть структура `var/db/...`

### 2. Совместимость версии кода с БД

Бэкап от 06.12.2025 должен быть совместим с кодом из ветки `main` на эту дату. Если код был изменён после этой даты, возможны проблемы.

### 3. Права доступа

После восстановления БД обязательно проверьте права:
```bash
chown -R pi:pi /home/pi/reacthome-daemon/var/db
```

### 4. Проверка успешности восстановления

**Признаки успешного восстановления:**
- ✅ Демон запущен и работает (`pm2 list` показывает `online`)
- ✅ В логах есть сообщение о загрузке записей из LevelDB
- ✅ Количество записей в БД > 100 (обычно 1000-3000)
- ✅ Файлы LevelDB присутствуют: CURRENT, MANIFEST-*, *.ldb, *.log
- ✅ Нет критических ошибок в логах (ошибки SQLite не критичны)

**Проверка после восстановления:**
```bash
# 1. Статус демона
pm2 list | grep daemon  # Должен быть "online"

# 2. Количество записей в БД
node -e "const {Level}=require('level');(async()=>{try{const db=new Level('var/db',{valueEncoding:'json'});let c=0;for await(const _ of db.iterator())c++;await db.close();console.log('Записей:',c);}catch(e){console.error('ERROR:',e.message);process.exit(1);}})();"

# 3. Проверка логов на ошибки
pm2 logs daemon --lines 100 | grep -iE "(error|Error|ERROR)" | grep -v "SQLITE_ERROR\|no such table: forms"

# 4. Проверка файлов БД
ls -lh var/db | wc -l  # Должно быть > 5
test -f var/db/CURRENT && echo "✅" || echo "❌"
```

**Некритичные ошибки (можно игнорировать):**
- `SQLITE_ERROR: no such table: forms` - ошибка в модуле assist/lang/ru.js, не влияет на LevelDB

   - ✅ Проверьте статус демона: `pm2 list | grep daemon`
   - ✅ Проверьте количество записей в БД (должно быть > 100)

   - ✅ Убедитесь, что все устройства подключаются
   - ✅ Проверьте работу основных функций
   - ⚠️ Ошибки SQLite (`no such table: forms`) можно игнорировать - они не критичны
