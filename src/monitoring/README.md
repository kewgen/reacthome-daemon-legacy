# Подпроект мониторинга

Этот подпроект содержит скрипты и документацию для мониторинга состояния устройств и системы.

## Структура

```
monitoring/
├── scripts/          # Скрипты мониторинга
├── docs/            # Документация по мониторингу
└── README.md        # Этот файл
```

## Скрипты

### monitor.js

Основной скрипт мониторинга устройств с терминальным UI на terminal-kit.

**Использование:**
```bash
node monitoring/scripts/monitor.js
```

**Особенности:**
- Трёхпанельный интерфейс с рамками (как в Midnight Commander)
- Фильтрация устройств по категориям, типам и помещениям
- Отображение параметров устройств в реальном времени
- Копирование информации в буфер обмена
- Подключение к WebSocket для получения обновлений состояния

**Управление:**
- `Tab` - Переключение между панелями
- `↑/↓` или `j/k` - Навигация по списку
- `Enter` - Выбор фильтра / Показать информацию об устройстве
- `c` - Копировать содержимое раздела "Устройство" в буфер обмена
- `y+c` - Копировать строку таблицы в буфер обмена
- `q` или `Ctrl+C` - Выход

### monitor-shield-devices-status.js

Скрипт для мониторинга состояния щитовых устройств (консольный вывод).

### monitor-shield-devices-status-ui-example.js

Пример скрипта мониторинга с UI на библиотеке blessed (устаревший, используется для справки).

### monitor-db-changes.js

Скрипт для мониторинга изменений в базе данных.

## Документация

- `DB_MONITORING.md` - Мониторинг базы данных
- `PM2_LOCAL_MONITORING.md` - Мониторинг процессов PM2

## Зависимости

Основной скрипт `monitor.js` требует:
- `terminal-kit` - для терминального UI
- `ws` - для WebSocket подключения
- `level` - для работы с базой данных LevelDB

Установка зависимостей:
```bash
npm install terminal-kit ws level
```

## Переменные окружения

- `REACTHOME_WS_URI` - URI WebSocket сервера (по умолчанию: `ws://192.168.88.4:3000`)
- `DB_PATH` - Путь к базе данных LevelDB (по умолчанию: `var/db`)
