# Инструкция по тестированию monitor.js на Raspberry Pi

## Быстрый старт

### 1. Подготовка окружения

```bash
# Подключение к Raspberry Pi
ssh pi@192.168.88.4

# Переход в директорию проекта
cd /home/pi/reacthome-daemon  # или путь к вашему проекту

# Проверка Node.js версии
node --version  # Должно быть v18.x.x или выше

# Проверка зависимостей
npm list terminal-kit ws
```

### 2. Установка системных зависимостей (опционально)

```bash
# Установка xclip для копирования в буфер обмена
sudo apt-get update
sudo apt-get install -y xclip

# Проверка установки
which xclip
```

### 3. Запуск скрипта

```bash
# Базовый запуск
node monitoring/scripts/monitor.js

# С указанием URI WebSocket (если отличается от дефолтного)
REACTHOME_WS_URI=ws://192.168.88.4:3000 node monitoring/scripts/monitor.js

# Или для локального сервера
REACTHOME_WS_URI=ws://localhost:3000 node monitoring/scripts/monitor.js
```

## Проверка работоспособности

### Базовые проверки

1. **Запуск без ошибок:**
   ```bash
   node monitoring/scripts/monitor.js
   ```
   Ожидается: UI загружается, подключается к WebSocket, загружает устройства

2. **Проверка подключения:**
   - В строке состояния должно отображаться количество устройств
   - Должна отображаться скорость обновлений WebSocket

3. **Проверка навигации:**
   - `Tab` - переключение между панелями
   - `↑/↓` или `j/k` - навигация по спискам
   - `Enter` - выбор фильтра/устройства
   - `q` или `Ctrl+C` - выход

### Функциональные проверки

1. **Фильтры:**
   - Выбор категории устройств
   - Выбор типа потребителя
   - Выбор помещения
   - Фильтр "Все"

2. **Таблица устройств:**
   - Отображение списка устройств
   - Выделение выбранного устройства
   - Прокрутка при большом количестве устройств

3. **Информация об устройстве:**
   - Отображение параметров устройства
   - Подсветка измененных параметров
   - Форматирование каналов актуаторов
   - Отображение поля `modified` как время

4. **Копирование:**
   - `c` - копирование информации об устройстве
   - `y+c` - копирование строки таблицы
   - Проверка работы в буфере обмена (если установлен xclip)

## Устранение проблем

### Проблема: Скрипт не запускается

**Ошибка:** `Cannot find module 'terminal-kit'`

**Решение:**
```bash
npm install terminal-kit ws
```

### Проблема: Не подключается к WebSocket

**Ошибка:** `WebSocket error` или `Устройства не найдены через WebSocket`

**Решение:**
1. Проверить, что WebSocket сервер запущен:
   ```bash
   netstat -tlnp | grep 3000
   # или
   ss -tlnp | grep 3000
   ```

2. Проверить URI WebSocket:
   ```bash
   # Установить правильный URI
   export REACTHOME_WS_URI=ws://192.168.88.4:3000
   node monitoring/scripts/monitor.js
   ```

3. Проверить доступность порта:
   ```bash
   telnet 192.168.88.4 3000
   # или
   curl -v http://192.168.88.4:3000
   ```

### Проблема: Курсор уходит за экран

**Симптом:** Курсор не виден или выходит за границы экрана

**Решение:**
- Уже исправлено в последней версии
- Проверить размер терминала: `echo $COLUMNS x $LINES`
- Перезапустить скрипт

### Проблема: Копирование не работает

**Симптом:** При нажатии `c` или `y+c` ничего не происходит

**Решение:**
1. Установить `xclip`:
   ```bash
   sudo apt-get install -y xclip
   ```

2. Если запускается через SSH без X11:
   - Скрипт выведет текст в консоль (fallback)
   - Можно скопировать вручную

### Проблема: Медленная работа

**Симптом:** UI тормозит при большом количестве устройств

**Решение:**
1. Проверить количество устройств (может быть слишком много)
2. Проверить использование памяти:
   ```bash
   top -p $(pgrep -f monitor.js)
   ```
3. Рассмотреть оптимизацию (батчинг обновлений)

## Логирование и отладка

### Включение отладочных сообщений

Скрипт содержит отладочные `console.log('[DEBUG]')` сообщения. Для их отключения можно:

1. Заменить на условное логирование:
   ```javascript
   if (process.env.DEBUG) {
     console.log('[DEBUG] ...');
   }
   ```

2. Или использовать переменную окружения:
   ```bash
   DEBUG=true node monitoring/scripts/monitor.js
   ```

### Проверка WebSocket соединения

```bash
# Проверить активные WebSocket соединения
netstat -an | grep 3000

# Или использовать tcpdump для анализа трафика
sudo tcpdump -i any -A 'port 3000'
```
