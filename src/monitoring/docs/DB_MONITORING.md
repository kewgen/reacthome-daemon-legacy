# Мониторинг изменений БД

**Зачем:** Отслеживание изменений в LevelDB для диагностики проблем, аудита и понимания динамики данных

## Описание

Система мониторинга отслеживает изменения в базе данных LevelDB и выводит их в реальном времени. Мониторинг показывает:
- ➕ Добавленные записи
- ➖ Удалённые записи  
- 🔄 Изменённые записи (с указанием изменённых полей)

## Использование

### Локальный мониторинг

```bash
# Мониторинг локальной БД с интервалом 5 секунд (по умолчанию)
node scripts/monitor-db-changes.js

# Мониторинг с указанием пути к БД и интервала
node scripts/monitor-db-changes.js /path/to/db 10

# Использование переменных окружения
DB_PATH=/path/to/db node scripts/monitor-db-changes.js
```

### Мониторинг БД на малинке

```bash
# Мониторинг БД на малинке с интервалом 5 секунд
./scripts/monitor-db-changes-on-pi.sh

# Мониторинг с указанием интервала
./scripts/monitor-db-changes-on-pi.sh 10
```

**Важно:** Скрипт автоматически останавливает демон перед началом мониторинга и перезапускает его после завершения.

## Формат вывода

Мониторинг выводит изменения в следующем формате:

```
╔═══════════════════════════════════════════════════════════════╗
║   Изменения в БД: 10.12.2025, 22:30:15                        ║
╚═══════════════════════════════════════════════════════════════╝

➕ Добавлено записей: 2
   • 60:66:13:b4:aa:df [device_43]
     {"type":43,"version":"2.2","ip":"172.16.0.5","online":true...}
   • a0:0a:e1:9e:9a:cb [device_37]
     {"type":37,"version":"2.2","ip":"172.16.0.10","online":true...}

🔄 Изменено записей: 1
   • 60:66:13:b4:aa:df [device_43]
     - online: false → true
     - timestamp: 1765394860609 → 1765394930156

📊 Статистика: добавлено: 2, удалено: 0, изменено: 1, без изменений: 1984
```

## Хранение снимков

Мониторинг сохраняет снимки состояния БД в файл `var/db-snapshot.json`. Этот файл используется для сравнения текущего состояния с предыдущим.

**Расположение снимка:**
- По умолчанию: `var/db-snapshot.json`
- Можно изменить через переменную окружения: `SNAPSHOT_FILE=/path/to/snapshot.json`

## Типы изменений

### Добавление записи
Мониторинг показывает:
- Ключ записи
- Тип записи (device_XX, site, script и т.д.)
- Предпросмотр значения (первые 100 символов)

### Удаление записи
Мониторинг показывает:
- Ключ удалённой записи
- Тип записи
- Старое значение (если доступно)

### Изменение записи
Мониторинг показывает:
- Ключ изменённой записи
- Тип записи
- Список изменённых полей с старыми и новыми значениями

## Примеры использования

### Мониторинг во время восстановления БД

```bash
# В одном терминале запускаем мониторинг
./scripts/monitor-db-changes-on-pi.sh 2

# В другом терминале выполняем восстановление
./scripts/restore-db-on-pi.sh backups/var-backup-20251209_230607.tar.gz
```

### Мониторинг конкретного устройства

```bash
# Запускаем мониторинг и фильтруем вывод по MAC адресу
./scripts/monitor-db-changes-on-pi.sh 5 | grep "60:66:13:b4:aa:df"
```

### Сохранение логов мониторинга

```bash
# Сохраняем вывод мониторинга в файл
./scripts/monitor-db-changes-on-pi.sh 5 | tee logs/db-monitoring-$(date +%Y%m%d_%H%M%S).log
```

## Ограничения

1. **Доступ к БД:** Для мониторинга БД на малинке необходимо остановить демон (скрипт делает это автоматически)
2. **Производительность:** Частые проверки (интервал < 1 секунды) могут нагружать систему
3. **Размер снимка:** Снимок БД хранится в памяти и на диске, для больших БД это может быть ресурсоёмко

## Устранение неполадок

### Ошибка "Database is not open"
- Убедитесь, что демон остановлен перед запуском мониторинга
- Проверьте, что БД не используется другим процессом

### Ошибка "Cannot find module 'level'"
- Убедитесь, что `NODE_PATH=./node_modules` установлен при запуске
- Проверьте, что модуль `level` установлен в `node_modules`

### Снимок не сохраняется
- Проверьте права доступа к директории `var/`
- Убедитесь, что достаточно места на диске

## Интеграция с другими инструментами

Мониторинг можно интегрировать с:
- Системами логирования (отправка изменений в OpenSearch, Elasticsearch)
- Системами алертинга (уведомления о критических изменениях)
- Системами бэкапирования (автоматическое создание бэкапов при изменениях)
