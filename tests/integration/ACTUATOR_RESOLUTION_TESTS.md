# Тесты для проверки гипотез проблемы резолва актуаторов

## Структура тестов

Каждый тест проверяет одну конкретную гипотезу из документа `ACTUATOR_RESOLUTION_PROBLEM.md`.

## Тест 1: Каналы не запрашиваются при начальной загрузке

**Файл:** `test-hypothesis-1-channels-not-initial-load.js`

**Гипотеза:** При старте `monitor.js` выполняется массовый GET для всех устройств, но каналы актуаторов не включаются в этот запрос.

**Что проверяет:**
- Массовый GET при старте не содержит каналов актуаторов
- Каналы не загружаются автоматически
- Состояния каналов (включая `bind`) отсутствуют после начальной загрузки

**Ожидаемый результат:** Тест подтверждает, что каналы не запрашиваются при начальной загрузке.

## Тест 2: Частичные обновления каналов без поля `bind`

**Файл:** `test-hypothesis-2-partial-updates-without-bind.js`

**Гипотеза:** Каналы часто приходят через WebSocket с частичными payload, в которых отсутствует поле `bind`.

**Что проверяет:**
- Процент обновлений каналов, содержащих поле `bind`
- Частота частичных обновлений без `bind`
- Корреляция между наличием `_context` и отсутствием `bind`

**Ожидаемый результат:** Тест подтверждает, что значительная часть обновлений каналов не содержит `bind`.

## Тест 3: Ограничительное условие дозапроса `bind`

**Файл:** `test-hypothesis-3-selected-actuator-restriction.js`

**Гипотеза:** Дозапрос состояния канала выполняется только если канал принадлежит выбранному актуатору.

**Что проверяет:**
- Дозапросы отправляются только для выбранного актуатора
- Каналы невыбранных актуаторов не дозапрашиваются
- При переключении актуатора дозапросы начинают работать

**Ожидаемый результат:** Тест подтверждает, что дозапрос ограничен выбранным актуатором.

## Тест 4: Асинхронность загрузки связанных устройств

**Файл:** `test-hypothesis-4-async-linked-devices.js`

**Гипотеза:** Устройства, упомянутые в `bind` каналов, могут быть еще не загружены в момент резолва.

**Что проверяет:**
- Количество каналов с `bind`, но без `linkedDevice`
- Время между появлением `bind` и загрузкой связанного устройства
- Эффективность механизма запроса отсутствующих устройств

**Ожидаемый результат:** Тест подтверждает, что связанные устройства загружаются асинхронно с задержкой.

## Тест 5: Неэффективный поиск связанных устройств

**Файл:** `test-hypothesis-5-inefficient-device-search.js`

**Гипотеза:** Поиск устройства по `bind` выполняется только по точному совпадению `id`, без учета возможных вариантов формата.

**Что проверяет:**
- Случаи, когда `bind` не совпадает с `id`, но устройство существует
- Эффективность fallback поиска по `code` и `name`
- Форматы `bind` и `id`, которые не совпадают
- Реальную логику поиска из monitor.js (строки 1871-1878)

**Ожидаемый результат:** Тест подтверждает, что поиск не находит устройства при несовпадении форматов.

## Тест 6: Интеграционный тест цепочки проблем

**Файл:** `test-hypothesis-6-problem-chain.js`

**Гипотеза:** Проблемы взаимодействуют друг с другом, создавая цепочку от начала до конца.

**Что проверяет:**
- Всю цепочку проблем от начала до конца
- Взаимодействие между проблемами
- Финальный результат в виде отсутствия резолва

**Ожидаемый результат:** Тест подтверждает комплексную природу проблемы.

## Тест 7: Результат в UI - показ "(не привязан)"

**Файл:** `test-hypothesis-7-ui-result.js`

**Гипотеза:** Из-за проблем с резолвом UI показывает каналы как "(не привязан)" даже когда привязки существуют.

**Что проверяет:**
- Симуляцию UI отображения каналов
- Проверку, что каналы с `bind` показываются как "(не привязан)"
- Проверку корректности отображения после резолва
- Реальную логику из monitor.js (строки 2540-2578)

**Ожидаемый результат:** Тест подтверждает некорректное отображение в UI.

## Тест 8: Механизм повторного резолва

**Файл:** `test-hypothesis-8-reresolution.js`

**Гипотеза:** При получении новых данных должен происходить пересчет `linkedDevice` для всех каналов.

**Что проверяет:**
- Пересчет `linkedDevice` при получении новых данных
- Обновление UI при изменении состояния резолва
- Эффективность механизма повторного резолва

**Ожидаемый результат:** Тест проверяет наличие и эффективность механизма повторного резолва.

## Запуск тестов

Все тесты можно запустить по отдельности:

```bash
# Тест гипотезы 1
node tests/integration/test-hypothesis-1-channels-not-initial-load.js

# Тест гипотезы 2
node tests/integration/test-hypothesis-2-partial-updates-without-bind.js

# Тест гипотезы 3
node tests/integration/test-hypothesis-3-selected-actuator-restriction.js

# Тест гипотезы 4
node tests/integration/test-hypothesis-4-async-linked-devices.js

# Тест гипотезы 5
node tests/integration/test-hypothesis-5-inefficient-device-search.js

# Тест гипотезы 6
node tests/integration/test-hypothesis-6-problem-chain.js

# Тест гипотезы 7
node tests/integration/test-hypothesis-7-ui-result.js

# Тест гипотезы 8
node tests/integration/test-hypothesis-8-reresolution.js
```

Или все тесты сразу:

```bash
node tests/integration/run-all-hypothesis-tests.js [ws://host:port]
```

Скрипт `run-all-hypothesis-tests.js`:
- Запускает все тесты последовательно
- Собирает общий отчет о результатах
- Сохраняет отчет в `hypothesis-tests-report.json`
- Выводит итоговую статистику

## Переменные окружения

- `REACTHOME_WS_URI` - URI WebSocket сервера (по умолчанию `ws://192.168.88.4:3000`)
- `TEST_TIMEOUT` - таймаут теста в миллисекундах (по умолчанию 30000 для большинства тестов, 60000 для теста гипотезы 2)

## Структура тестов

Каждый тест:
1. Подключается к WebSocket серверу
2. Загружает список устройств через LIST
3. Запрашивает данные устройств и каналов через GET
4. Анализирует поведение системы
5. Формулирует вывод о подтверждении/опровержении гипотезы

## Интерпретация результатов

- **✅ ГИПОТЕЗА ПОДТВЕРЖДЕНА** - проблема существует и подтверждена тестом
- **⚠️ ГИПОТЕЗА ЧАСТИЧНО ПОДТВЕРЖДЕНА** - проблема существует, но не критична
- **❓ ГИПОТЕЗА НЕ ПОДТВЕРЖДЕНА** - проблема не обнаружена или решена
