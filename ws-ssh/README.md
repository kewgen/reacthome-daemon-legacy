# ws-ssh

SSH клиент для подключения к демону ReactHome через внешний WebSocket gate.

## Описание

Утилита для удаленного доступа к терминалу демона через внешний WebSocket сервер `gate.reacthome.net`. Поддерживает интерактивный режим и batch-режим для автоматизации.

## Установка

```bash
cd ws-ssh
npm install
```

## Использование

### Интерактивный режим

```bash
# Запуск с выбором демона из списка
node index.js

# Запуск с указанным UUID
node index.js fd6765f1-ed61-4ae4-8d72-9a078a9f4316
```

### Batch-режим

Выполнение команд без интерактивного TTY:

```bash
node index.js <uuid> --cmd "pwd" --cmd "ls" --wait-ms 2000
```

### Переменные окружения

- `DAEMON_ID` - UUID демона (если указан, выбор из списка не предлагается)
- `GATE_URL` - URL WebSocket gate (по умолчанию: `wss://gate.reacthome.net`)
- `WIRE_MODE` - Режим протокола: `plain` (по умолчанию) или `prefixed`
- `DEBUG` - Включить отладочный вывод: `1` или `0`
- `WAIT_MS` - Время ожидания в batch-режиме (по умолчанию: 1500)

### Параметры командной строки

- `--cmd <command>` - Команда для выполнения в batch-режиме (можно указать несколько)
- `--wait-ms <ms>` - Время ожидания после последней команды в batch-режиме
- `--daemon <uuid>` - UUID демона
- `--debug` - Включить отладочный вывод

## Примеры

```bash
# Интерактивное подключение
node index.js

# Подключение к конкретному демону
node index.js fd6765f1-ed61-4ae4-8d72-9a078a9f4316

# Batch-режим: выполнить команды и выйти
node index.js fd6765f1-ed61-4ae4-8d72-9a078a9f4316 --cmd "pwd" --cmd "ls"

# С отладкой
DEBUG=1 node index.js fd6765f1-ed61-4ae4-8d72-9a078a9f4316

# Через переменную окружения
DAEMON_ID=fd6765f1-ed61-4ae4-8d72-9a078a9f4316 node index.js
```

## Настройка известных демонов

Отредактируйте массив `KNOWN_DAEMONS` в файле `index.js`:

```javascript
const KNOWN_DAEMONS = [
  { id: 'fd6765f1-ed61-4ae4-8d72-9a078a9f4316', name: 'Почтовая (Архитекторов)' },
  { id: 'd31775ae-19e8-40c9-81df-d6d672379563', name: 'Лучистое (Миндальный)' },
];
```

**Соответствия названий:**
- **Почтовая** = **Архитекторов** = `fd6765f1-ed61-4ae4-8d72-9a078a9f4316`
- **Лучистое** = **Миндальный** = `d31775ae-19e8-40c9-81df-d6d672379563`

## Протокол

Утилита использует протокол WebSocket с подпротоколом `listen` для подключения к gate серверу. Сообщения типа `pty` передаются в формате JSON:

```json
{
  "type": "pty",
  "chunk": "команда\n",
  "rows": 24,
  "cols": 80
}
```

По умолчанию используется режим `plain` (plain JSON). Режим `prefixed` (с префиксом UUID сессии) доступен для совместимости со старыми версиями.

## Бэкап базы данных

### Бэкап одного умного дома

Для создания бэкапа БД конкретного демона используйте скрипт `backup-db.js`:

```bash
# Бэкап с указанием UUID демона (сохраняется в ../backups)
node backup-db.js fd6765f1-ed61-4ae4-8d72-9a078a9f4316

# Бэкап с указанием директории для сохранения
node backup-db.js fd6765f1-ed61-4ae4-8d72-9a078a9f4316 ./my-backups
```

**Альтернатива:** Используйте bash-скрипт `backup-db.sh`:

```bash
# Бэкап с указанием UUID демона (сохраняется в ../backups)
./backup-db.sh d31775ae-19e8-40c9-81df-d6d672379563

# Бэкап с указанием директории для сохранения
./backup-db.sh d31775ae-19e8-40c9-81df-d6d672379563 ./my-backups
```

### Бэкап всех умных домов

Для создания бэкапов всех известных УД используйте скрипт `backup-all.js`:

```bash
# Бэкап всех УД в директорию по умолчанию (../backups - проектная папка)
node backup-all.js

# Бэкап всех УД в указанную директорию
node backup-all.js ./my-backups
```

Скрипт автоматически:
1. Перебирает все известные демоны из списка
2. Создаёт бэкап для каждого через `backup-db.js`
3. Выводит итоговый отчёт с результатами
4. Показывает список созданных файлов

**Как работают скрипты:**
1. Подключаются к демону через WebSocket SSH
2. Создают архив `var/db/` на удалённом сервере
3. Передают архив через base64 в терминале
4. Сохраняют локально в указанную директорию

**Примечание:** 
- БД хранится в `var/db/` на удалённом демоне (LevelDB формат)
- По умолчанию бэкапы сохраняются в проектной папке `../backups` (на уровень выше `ws-ssh`)
- Все скрипты бэкапа автоматически создают директорию для сохранения, если её нет
